# 전체 목표 대비 현재 구성 감사

기준 구현: 현재 승인 브랜치의 구현. 최신 native 이벤트 경로는 NATIVE_EVENT_INGRESS.md 참조. 이 문서는 범위를 줄이는 새
목표가 아니다. 부분 검사 통과를 전체 구성 완료로 해석하지 않도록 현재 코드 경로와
남은 증거를 대조한 것이다. **전체 목표는 미완료**다.

## 의미 대조와 관측값의 경계

SessionRuntime::retain_input은 일반 원문에 임의의 support/refute를 부여하지 않고 불충분한
관측으로 보존한다. 입력의 SHA 키 일치나 기록 성공을 명제의 참/거짓 판정으로 바꾸지 않는다.
현재 Re-evidence 구현은 **기록된 같은 연결 관측**을 비교한다. 따라서 세션 원문 저장이
작동한다는 사실만으로 “일반 대화의 명제 대조와 자동 재검증까지 완성”이라고 할 수 없다.
기존 SWEGCA 코어를 외부 분류기로 대체하거나 지원 근거 없는 판정값을 만들면 안 된다.

## 메모리 개선의 정확한 범위

원문 인코딩 복제 제거와 64KiB 스트리밍 관측 복구는 실제 개선이다. 64KiB 추적 예산에서
2MiB 원경험 복구를 검사했지만, 고정 스택과 호출자 버퍼까지 64KiB라는 의미가 아니다.
Main의 모든 연결·봉인된 경험·키 색인이 상주하는 구조는 별개 문제다. 저장 예산이
500GB로 설정됐다는 이유로 500GB 경험 그래프가 4GB 안에서 동작한다고 판단하지 않는다.

## 실제 통합에서 필요한 결정과 근거

사용자 원본과 현재 코드의 자연 입력 판정 경계는 `ARCHITECTURE_INPUT_GAPS.md`에
함수 수준으로 대조했다. 원본의 외부 judge 인자를 새 의미 판정기의 구현 근거로 간주하지 않는다.

- 현재 데스크톱 앱과 별도 app-server 클라이언트는 서로 다른 통합·배포 대상이다.
  사용자가 Codex 데스크톱을 첫 대상으로 다양한 에이전트를 지원하도록 지정했다. 두 구현을 같은 것으로 간주하지 않는다.

- 연결 진행: `swegca-app-server-proxy` 실행부가 전달받은 세 스트림에서 VRS 초기화,
  정적 세션 부착/재개, 기록 확인 후 양방향 원문 전달, 반쪽 연결 종료를 수행한다.
  실제 실행 파일과 VRS 자식 프로세스 검증은 통과했지만 데스크톱 설치는 아직 없다.
  동적 세션·전역 이벤트, 미완료 요청 복구, agent 문맥에 Recall/Replay 반영, 프로세스
  합산 자원 한도와 입력 지연 검증은 남아 있다. 상세: APP_SERVER_WIRE_OWNER.md.

- `thread/started` 서버 알림으로 새 세션의 임시 VRS 생성·기존 세션 재개를 연결했다.
  명시적 종료 세션은 코어 상태 규칙으로 재개를 거부하며 Main 병합 점유를 남기지 않는다.
  사용자 입력에서는 세션 생성/복구를 시도하지 않는다. 세션 ID가 아직 없는 최초
  `thread/start` 요청·전역 메시지의 경험 연결과 실제 데스크톱 설치는 여전히 미완료다.

- 호스트 프로토콜 11: native event에 연결된 세션 identity를 포함하여 선택·기록을
  하나의 호스트 호출로 처리한다. 프록시의 입력별 RPC 왕복이 2회에서 1회로 줄었다.
  이는 구조적 개선이며 입력→Recall 1ms 요구를 달성했다는 측정 증거는 아니다.

- 성공한 Replay의 봉인된 context 식별자를 통해 다른 임시 연결을 찾는 보조 경로를
  추가했다(`CONTEXT_CONTINUATION.md`). 정확 cue·기존 연결이 없을 때만 조회하며
  맥락 일치를 강화/진실 판정으로 사용하지 않는다. Main 전체의 context 포털 및
  자연어 의미 연결 완성으로 간주하지 않는다.

- 후속 구현으로 PersistentMainGraph가 기록된 context→연결 구간을 소유하고,
  같은 맥락이 다른 연결에 걸쳐 있으면 코어 분기를 통해 Main의 다른 주소 지역까지
  조회한다. 종료 세션 병합·복구·세대 검증에 연결됐다. 이는 기록된 맥락 관계의
  포털이며, 일반 자연어 의미 판단·전체 공유 경험 그래프·디스크 적재 완성은 아니다.
- 사용자가 region/portal 등 미정 설계를 위임했다. DELEGATED_DESIGN.md에 새 구성 결정을 기록했다. 공개 원본에서 확인되지 않은
  로컬 untracked 파일이나 폐기된 후보를 설계 근거로 채택하지 않는다. 이미 확정된 셔플·3상
  규칙에 대해서는 같은 설명을 다시 요구하지 않는다.
- 위 질문이 모든 독립 구현을 막는다는 뜻은 아니다. 다만 해당 선택에 종속된 호스트 설치나
  근거 없는 그래프 의미 규칙을 추측해 완료 상태로 만들지 않는다.

## 다음 구현이 해결해야 할 핵심

1. 지정한 실제 클라이언트의 입력 전·전체 이벤트·명시적 종료 및 작업 호출 연결.
2. 사용자 원본 아키텍처를 따르는 전체 그래프 구성과 상주 메모리가 제한된 탐색·복구.
3. 현재 명제 대조·필요한 재검증의 실제 자동 경로. 지원 근거 없는 참/거짓 추론 금지.
4. 선택 원문 반환의 메모리 경계, 실제 장치 자원 프로파일과 측정된 지연 실패 해결.

이 항목들을 다루지 않은 성능 수치·테스트 수 증가만으로 전체 목표를 완료 처리하지 않는다.

### 초기 통신 연결의 진행

세션 ID 없는 초기화·스레드 생성 요청·전역 알림을 원문 그대로 보존하는
연결 소유 어댑터와 Wire 경로를 추가했다. 요청 ID와 기록된 순번으로 응답을
동일 연결에 귀속시키며, 사용자 입력의 잘못된 형식을 전역 내용으로 우회하지
않는다. 관련 검사 424개 통과. 아직 호스트·프록시 설정에서 이 경로를 선택하지
않으므로 전역 이벤트의 실제 VRS 저장 완료로 간주하지 않는다.

후속 호스트 프로토콜 12에서 연결 소유 출처의 저장·복구·응답 원경험 대조를
연결했고, 프록시 `connectionSession` 설정으로 실제 실행 경로에 부착한다.
실제 프록시/VRS 프로세스와 시험용 양방향 소켓 검사 2,238개가 통과했다.
초기 메시지 5개의 재시작 복구, 복구된 요청에 대한 응답 기록, 중복 재사용,
잘못된 입력 거부와 EOF 후 병합 0건을 확인했다. 실제 데스크톱 설치와
새 스레드 계보 연결·진행 중 요청 자동 복구·문맥 주입은 여전히 미완료다.

진행 중 요청 복구를 위한 `swegca/agent/original` 조회를 추가했다. 세션·순번으로
기존 원경험 주소를 찾아 VRS 읽기 검증과 원문 지문 대조를 거친다. 재시작 후
초기 원경험 5개와 요청·응답 계보를 확인했고 실행 검사 2,282개가 통과했다.
발신 방향의 영속 보존은 아직 없어 자동 요청 복구 완료로 판단하지 않는다.

호스트 프로토콜 13: 프록시의 실제 수신 방향을 원경험과 동일 체크섬 안에
보존한다. 전체 읽기와 스트리밍 복구 모두 방향을 반환하고, 중복 기록의
방향 변경 및 요청과 같은 방향의 응답을 거부한다. 저장 검사 439개,
실제 프로세스 검사 2,307개 통과. 방향 정보 없는 기록은 추측하지 않는다.
프록시 진행 중 요청 목록의 자동 재구성은 후속 작업이다.

프록시의 진행 중 요청 자동 재구성을 연결했다. 시작 시 등록된 세션과 실행 중
thread/started로 다시 발견한 세션 모두 원경험·발신 방향·응답 계보를 읽어
미응답 요청만 복구한다. 실제 프로세스 검사 2,337개 통과: 양방향 동일 ID의
응답 분리 및 동적 세션 요청 복구, 재시작 후 응답 계보 저장을 확인했다.
복구는 아직 해당 세션의 기록을 순회하므로 긴 세션에서의 시작 비용 개선은
남는다. 실제 데스크톱 설치·회상 문맥 반영·자원/지연 목표는 미완료다.

데스크톱 표준입출력을 프록시 소켓에 연결하는 C++ 실행기를 추가했다
(`DESKTOP_HOST.md`). 설치된 앱 코드의 CODEX_CLI_PATH 선택 경로를 확인했다.
실제 실행기·프록시·VRS와 시험 백엔드의 왕복 및 종료/자식 정리 검사까지
2,385개 통과. 설치된 앱의 실행 설정은 변경하지 않았고, 전체 CLI 호출을
받는 배포 래퍼·문맥 주입·프로세스 합산 자원/입력 지연은 남아 있다.

데스크톱 백엔드 인자를 받는 C++ 래퍼를 연결했다. 설치된 앱의 두 app-server
인자 순서를 처리하고 원래 인자 벡터를 보존한다. 표준입출력 서버는 VRS
실행기로, 버전/도움말/스키마 생성은 실제 백엔드로 전달한다. 라우팅 검사
33개와 래퍼를 포함한 실행 검사 2,385개 통과. 실제 앱 설치와 영속 실행
설정, 별도 CLI 에이전트 포착은 아직 완료하지 않았다.

영속 실행 `ensure`를 연결했다. 기존 루트 잠금 후 빈 루트만 생성하고, 기존
Main은 검증 복구한다. 부분 초기화·손상·잠금 실패를 재생성으로 처리하지
않는다. 같은 데스크톱 설정으로 두 번 시작하여 원경험 순번 보존/증가를
확인했다. Runtime 186개, 래퍼 33개, 프로세스 2,389개 검사 통과.
실제 앱 설치 및 명시적 세션 종료 연결은 여전히 남아 있다.

기존 대화 재개 경로의 누락을 수정했다. 클라이언트 thread/resume의 명시적
threadId로 임시 VRS를 연결·복구하며 thread/started 알림이 없어도 후속
사용자 입력을 받을 수 있다. 실제 재시작·재개·입력·다시 복구 검사 포함
프로세스 2,393개, 이벤트 215개, Wire 61개 통과. 잘못된 방향/형식의 재개는
거부하고, 사용자 turn 입력에서의 세션 탐색 금지는 유지한다.

재개 요청 ID 충돌이 원경험 저장 뒤에 발견되는 순서 결함을 수정했다.
복구된 미응답 목록과 새 요청을 저장 전에 대조한다. 입력 전체의 추가 해시는
Recall 앞에 넣지 않았다. 충돌 재개 요청의 전송 0건, 저장 순번 유지 및 기존
원경험 불변을 실제 재시작 검사로 확인했다. Wire 66개, Pump 88개,
프로세스 2,453개 검사 통과.

프로토콜 14에서 native 원문과 VRS RPC의 크기 한도를 분리했다. JSON 포장으로
커진 입력·복구 응답이 원문 한도에 걸리던 경로를 수정하고, 시작 시 호스트
수용 한도를 대조한다. 4KB 미만 원문이 포장 후 4KB를 넘는 저장·복구와
잘못된 호스트 한도의 시작 거부를 포함해 프로세스 검사 2,457개 통과.
임의 크기 첨부·합산 메모리 제한의 완성으로 판단하지 않는다.

시작·재개보다 먼저 오는 스레드 조회/상태 메시지가 세션 미연결로 거부되는
누락을 수정했다. 명시적 threadId를 가진 비입력 메시지는 기존 코어 기록
분기를 통해 연결하며, 사용자 입력과 원요청 없는 응답의 세션 탐색은 금지한다.
이전 대화 조회→재개→입력→복구를 포함한 프로세스 2,459개, Wire 74개,
Pump 88개 검사 통과. 반환된 대화 내용의 의미 검증 완성과는 별개다.

Replay/Re-evidence의 MCP 응답 구성에서 이스케이프된 결과 복사본과 합쳐진
전체 응답 버퍼를 제거하고 스트림으로 출력한다. 기존 텍스트/구조화 결과의
동일성은 유지한다. JSON 스트림 15개, 실제 프로세스 2,495개 검사 통과.
전체 Replay 원경험 보유와 hex 결과 버퍼는 여전히 남으며, 부분 읽기를
완료된 Replay로 바꾸지 않았다. 전체 4GB 제한 달성 증거는 아니다.

전체/부분 Replay의 contentHex를 4KiB 고정 변환 버퍼로 직접 출력하여 원문
두 배 크기의 hex 문자열과 이를 포함한 결과 본문 버퍼를 제거했다. 768KiB
데이터를 포함한 원경험을 2MiB PMR 예산으로 복구→Recall→전체 Replay→
Re-evidence 하는 실제 프로세스 검사가 통과했다. JSON 스트림 25개,
프로세스 2,560개 통과. 전체 원경험 한 개의 메모리 보유는 여전히 남는다.

데스크톱 stdin 쓰기 시작→코어 Recall 진입 진단을 추가했다

초과한다. 실제 GUI 및 전체 규모 지연 요구는 완료되지 않았다.
