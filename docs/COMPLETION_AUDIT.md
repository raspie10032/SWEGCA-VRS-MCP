# 전체 목표 대비 현재 구성 감사

기준 구현: 현재 승인 브랜치의 구현. 최신 native 이벤트 경로는 NATIVE_EVENT_INGRESS.md 참조. 이 문서는 범위를 줄이는 새
목표가 아니다. 부분 검사 통과를 전체 구성 완료로 해석하지 않도록 현재 코드 경로와
남은 증거를 대조한 것이다. **전체 목표는 미완료**다.

## 의미 대조와 관측값의 경계

SessionRuntime::retain_input은 일반 원문에 임의의 support/refute를 부여하지 않고 불충분한
관측으로 보존한다. 입력의 SHA 키 일치나 기록 성공을 명제의 참/거짓 판정으로 바꾸지 않는다.
현재 Re-evidence 구현은 **기록된 같은 연결 관측**을 비교한다. 따라서 세션 원문 저장이
작동한다는 사실만으로 “일반 대화의 명제 대조와 자동 재검증까지 완성”이라고 할 수 없다.
기존 SWEGCA 코어를 외부 분류기로 대체하거나 지원 근거 없는 판정값을 만들면 안 된다.

## 메모리 개선의 정확한 범위

원문 인코딩 복제 제거와 64KiB 스트리밍 관측 복구는 실제 개선이다. 64KiB 추적 예산에서
2MiB 원경험 복구를 검사했지만, 고정 스택과 호출자 버퍼까지 64KiB라는 의미가 아니다.
Main의 모든 연결·봉인된 경험·키 색인이 상주하는 구조는 별개 문제다. 저장 예산이
500GB로 설정됐다는 이유로 500GB 경험 그래프가 4GB 안에서 동작한다고 판단하지 않는다.

## 실제 통합에서 필요한 결정과 근거

사용자 원본과 현재 코드의 자연 입력 판정 경계는 `ARCHITECTURE_INPUT_GAPS.md`에
함수 수준으로 대조했다. 원본의 외부 judge 인자를 새 의미 판정기의 구현 근거로 간주하지 않는다.

- 현재 데스크톱 앱과 별도 app-server 클라이언트는 서로 다른 통합·배포 대상이다.
  사용자가 Codex 데스크톱을 첫 대상으로 다양한 에이전트를 지원하도록 지정했다. 두 구현을 같은 것으로 간주하지 않는다.

- 연결 진행: `swegca-app-server-proxy` 실행부가 전달받은 세 스트림에서 VRS 초기화,
  정적 세션 부착/재개, 기록 확인 후 양방향 원문 전달, 반쪽 연결 종료를 수행한다.
  실제 실행 파일과 VRS 자식 프로세스 검증은 통과했지만 데스크톱 설치는 아직 없다.
  동적 세션·전역 이벤트, 미완료 요청 복구, agent 문맥에 Recall/Replay 반영, 프로세스
  합산 자원 한도와 입력 지연 검증은 남아 있다. 상세: APP_SERVER_WIRE_OWNER.md.

- `thread/started` 서버 알림으로 새 세션의 임시 VRS 생성·기존 세션 재개를 연결했다.
  명시적 종료 세션은 코어 상태 규칙으로 재개를 거부하며 Main 병합 점유를 남기지 않는다.
  사용자 입력에서는 세션 생성/복구를 시도하지 않는다. 세션 ID가 아직 없는 최초
  `thread/start` 요청·전역 메시지의 경험 연결과 실제 데스크톱 설치는 여전히 미완료다.

- 호스트 프로토콜 11: native event에 연결된 세션 identity를 포함하여 선택·기록을
  하나의 호스트 호출로 처리한다. 프록시의 입력별 RPC 왕복이 2회에서 1회로 줄었다.
  이는 구조적 개선이며 입력→Recall 1ms 요구를 달성했다는 측정 증거는 아니다.

- 성공한 Replay의 봉인된 context 식별자를 통해 다른 임시 연결을 찾는 보조 경로를
  추가했다(`CONTEXT_CONTINUATION.md`). 정확 cue·기존 연결이 없을 때만 조회하며
  맥락 일치를 강화/진실 판정으로 사용하지 않는다. Main 전체의 context 포털 및
  자연어 의미 연결 완성으로 간주하지 않는다.

- 후속 구현으로 PersistentMainGraph가 기록된 context→연결 구간을 소유하고,
  같은 맥락이 다른 연결에 걸쳐 있으면 코어 분기를 통해 Main의 다른 주소 지역까지
  조회한다. 종료 세션 병합·복구·세대 검증에 연결됐다. 이는 기록된 맥락 관계의
  포털이며, 일반 자연어 의미 판단·전체 공유 경험 그래프·디스크 적재 완성은 아니다.
- 사용자가 region/portal 등 미정 설계를 위임했다. DELEGATED_DESIGN.md에 새 구성 결정을 기록했다. 공개 원본에서 확인되지 않은
  로컬 untracked 파일이나 폐기된 후보를 설계 근거로 채택하지 않는다. 이미 확정된 셔플·3상
  규칙에 대해서는 같은 설명을 다시 요구하지 않는다.
- 위 질문이 모든 독립 구현을 막는다는 뜻은 아니다. 다만 해당 선택에 종속된 호스트 설치나
  근거 없는 그래프 의미 규칙을 추측해 완료 상태로 만들지 않는다.

## 다음 구현이 해결해야 할 핵심

1. 지정한 실제 클라이언트의 입력 전·전체 이벤트·명시적 종료 및 작업 호출 연결.
2. 사용자 원본 아키텍처를 따르는 전체 그래프 구성과 상주 메모리가 제한된 탐색·복구.
3. 현재 명제 대조·필요한 재검증의 실제 자동 경로. 지원 근거 없는 참/거짓 추론 금지.
4. 선택 원문 반환의 메모리 경계, 실제 장치 자원 프로파일과 측정된 지연 실패 해결.

이 항목들을 다루지 않은 성능 수치·테스트 수 증가만으로 전체 목표를 완료 처리하지 않는다.

### 초기 통신 연결의 진행

세션 ID 없는 초기화·스레드 생성 요청·전역 알림을 원문 그대로 보존하는
연결 소유 어댑터와 Wire 경로를 추가했다. 요청 ID와 기록된 순번으로 응답을
동일 연결에 귀속시키며, 사용자 입력의 잘못된 형식을 전역 내용으로 우회하지
않는다. 관련 검사 424개 통과. 아직 호스트·프록시 설정에서 이 경로를 선택하지
않으므로 전역 이벤트의 실제 VRS 저장 완료로 간주하지 않는다.

후속 호스트 프로토콜 12에서 연결 소유 출처의 저장·복구·응답 원경험 대조를
연결했고, 프록시 `connectionSession` 설정으로 실제 실행 경로에 부착한다.
실제 프록시/VRS 프로세스와 시험용 양방향 소켓 검사 2,238개가 통과했다.
초기 메시지 5개의 재시작 복구, 복구된 요청에 대한 응답 기록, 중복 재사용,
잘못된 입력 거부와 EOF 후 병합 0건을 확인했다. 실제 데스크톱 설치와
새 스레드 계보 연결·진행 중 요청 자동 복구·문맥 주입은 여전히 미완료다.

진행 중 요청 복구를 위한 `swegca/agent/original` 조회를 추가했다. 세션·순번으로

기존 prepare_refinement를 호출하고 강도·revision을 커밋하지 않는다. 보고서의
strength/after_revision은 여전히 후보 투영값이며 저장 완료를 뜻하지 않는다.

비복사 ReplayComparison은 발급 경로·원경험·cue·기억 head·관측 경계를 묶는다.

허용한다. 다른 세션/다른 관측 경계/역행 step은 거부하며, 충돌 이후 추가된
관측도 현재 저장 상태에서 다시 평가한다. 이 과정은 원경험 추가나 강도 중복
갱신을 하지 않는다. 세션 검사 1,130개 및 런타임 검사 186개 통과.

연결했다. 응답 reEvidencePerformed로 실제 재검증 여부를 구분한다. 기존
Runtime의 명시적 저수준 평가 호출은 남아 있다. MCP 프로세스 검사 2,561개,
JSON 양 경로 각 13,279개, framing 29개, wrapper 33개 통과. 자동 후보 선택,
자연 입력의 검증 가능한 관측 연결, 에이전트 문맥 반영, 전체 4단계 완성 및
실제 앱 설치의 증거로 간주하지 않는다.

(Replay, seed, step) 오버로드를 삭제하여 모든 공개 re_evidence 호출이

상태에서 소멸 후 재시작 복구도 검사했다. 실제 앱 자동 예약·poll 및 입력 1ms
완료의 증거는 아니다. CPU 6,7 및 최대 2개 컴파일 제한을 유지했다.


stdio 호스트의 automaticWork 설정에 최초 예약·자동 poll을 연결했다. 초기화 후
유휴 시와 명시적 세션 종료 성공 후에 기존 Runtime 스케줄러를 진행한다. 설정의
seed/step을 그대로 쓰고 종료·발행되지 않은 원천은 기존 SWEGCA 경로에서 제외한다.
입력이 버퍼/FD에 있거나 부분 프레임이면 입력을 우선하며, 작업이 있을 때만 유휴
10ms 간격으로 확인한다. 설정이 없으면 기존 차단 읽기에 poll을 추가하지 않는다.

프레임 35개, 실제 프로세스 3,092개 통과. 별도 work/poll 호출 없이 병합·재시작
복구, 활성 세션/EOF의 비종료를 확인했다. 저장 한도 소진 시 자동 Main 실패로
종료 코드 2를 내며 잘못된 프레임 오류 응답을 만들지 않고, 한도 복구 후 영속
대기 원천을 처리하는 경로도 확인했다. 실제 앱 설치/종료 조작 연결과 commit 중
새 입력의 1ms 지연 상한은 남아 있다. 내부 LLM 호출과 모델 성능평가는 하지 않았다.

호스트 RPC가 이미 소유한 app-server 원문 문자열을 AgentEvent로 이동하여 동일
원문의 추가 사본을 제거했다. 동일 PMR 자원만 허용하며 기존 JSON/세션/입력 검증을
그대로 통과한 뒤 원문 버퍼를 이전한다. 응답 결합과 hook 경로는 기존대로다.
SWEGCA 판정·cue 생성·기억 단계 순서는 변경하지 않았다.

어댑터 243개, JSON 스트림 13,279개, 실제 호스트 프로세스 3,100개 검사를 통과했다.
큰 원문의 주소 동일성, 바이트 보존, 이동 후 필드, 연결 범위, 다른 할당자 및 잘못된
입력 거부를 확인했다. 1MiB 사례에서 생성 후 유지 메모리가 원문 크기 이상 감소한다.
파싱 중 임시 할당이 최대 사용량을 결정하므로 같은 크기의 peak 감소 주장은 하지 않는다.

benchmarks/results/desktop-{before,after}-native-transfer.jsonl에 각 5회 측정을 보존했다.
빈 Main/새 임시 세션의 런처 stdin 쓰기 시작→코어 Recall 진입 중앙값은
128B 0.026600→0.027461ms, 4KiB 0.044480→0.040660ms,
64KiB 0.208332→0.215902ms, 1MiB 3.050291→2.617896ms였다.
1MiB는 변경 전후 모두 5회 전부 1ms를 초과했다. 표본이 적고 흔들림이 있어 일반적인
속도 향상률이나 실제 설치 앱/큰 Main/동시 병합의 상한 증거로 해석하지 않는다.

추가 진단: desktop-native-transfer-stages.jsonl은 단계 마커가 포함된 별도 실행이다.
1MiB 입력의 단계별 차이 중앙값은 프록시 프레임 수신 1.0705ms, 프록시 적응
0.4531ms, RPC 인코딩 0.3867ms, 호스트 프레임 수신 0.8473ms,
호스트 외부 JSON 파싱 0.3506ms, native 적응 0.1141ms,
cue 준비 0.1708ms, 이후 Recall 진입 0.4615ms였다.
프레임 수신 구간에는 송신 측·스케줄링·할당도 포함되고, 마커 출력 자체의 비용도
있으므로 이 값으로 시스템 호출이나 파싱만의 비용을 단정하지 않는다.

4KiB 수신 staging을 64KiB로 늘리고 소켓 구분자 탐색을 memchr로 바꾼 실험은
채택하지 않았다. 마커 없는 5회 측정의 1MiB 중앙값은 2.958619ms로 직전
2.617896ms보다 개선되지 않았다. 실험 원자료는 desktop-rejected-64k-framing.jsonl.
추가 고정 메모리를 정당화하지 못하므로 두 변경 모두 되돌렸다. 현재 production
코드는 577a736과 동일하며 새 성능 개선을 주장하지 않는다.
64KiB 전후 및 128KiB 이상의 원문/NUL/후속 프레임 보존 검사는 남겼고,
복원된 코드에서 소켓 64개, stdio 프레임 35개, 펌프 95개 검사를 통과했다.
다음 병목 작업에서는 전체 원문을 RPC 문자열로 다시 인코딩·해제·재파싱하는
전송 구조와 parser 할당 비용을 구분해야 한다. 원문·입력 검증 생략은 허용하지 않는다.

JSON 문자열 디코딩의 확장 할당을 제거했다. 이스케이프가 없는 문자열은 단일
구간 복사를 유지한다. 이스케이프 문자열은 동일 decoder의 측정 경로에서 정확한
UTF-8 출력 길이를 구하고 한 번 예약한 뒤 같은 규칙으로 출력한다. 제어문자,
서로게이트 쌍, 잘못된 escape/UTF-8 검증은 유지하며 별도 의미 판정은 없다.

json-parse-memory-{before,after}.jsonl에서 1,048,587바이트의 native JSON 문자열
디코딩 유지 예약량이 2,097,171→1,048,588바이트, 최대 예약량이
3,145,757→1,048,588바이트로 감소했다. 이 값은 decoder의 PMR 요청이며
입력 버퍼/RSS/전체 프로세스 메모리 수치가 아니다. 정확한 출력 크기+1 예산의
대형 envelope, 모든 Unicode 출력 폭과 escape, malformed tail 거부를 추가했다.
JSON SIMD 및 scalar 각각 13,291개, 어댑터 243개, 호스트 프로세스 3,093개 통과.
make build/json-parse-memory-bench로 같은 독립 측정을 재현할 수 있다.

desktop-exact-string-allocation.jsonl의 빈 Main/새 임시 세션 각 5회 측정은
입력 128B/4KiB/64KiB/1MiB 중앙값 0.021220/0.039000/0.187892/3.498194ms.
1MiB 5회 모두 1ms 초과다. 이번 변경은 입증된 메모리 감소로 채택하며,
전체 지연 향상이나 1ms 완료는 주장하지 않는다. 작은 단일 decoder 시간보다
실제 다중 프로세스 경로를 계속 기준으로 삼는다.

Main의 ConnectionRegions 준비 과정에서 기존/신규 연결 키 전체를 벡터에 복사하고
정렬하던 과정을 제거했다. 정렬된 두 map의 고유 키를 순차 병합하여 개수를 세고,
두 번째 순회에서 기존 SWEGCA region_partition_end의 경계대로 노드만 준비한다.
32,768개 신규 연결은 추가 32KiB 예산으로 128개 지역 발행에 성공했다.
지역 66,255개 및 Main 그래프 4,700개 검사 통과(할당 실패 지점 913개).
기존 원경험·검증 보고서·강도·주소와 영속 발행 후 무할당 commit을 유지했다.
MainGraph의 Entry/ExperienceSequence 및 cue/context 색인 자체는 아직 전체 상주하며,
디스크 적재·퇴거와 전체 4GB 운용 완료로 해석하지 않는다.

MainSources의 캐시 해제에서 캐시가 없는 과거 원천까지 매번 전부 방문하던 순회를
제거했다. 기존 Source 안의 연결 목록으로 활성/준비/복구 캐시만 추적하며, 워커가
실행되기 전에 Main에서 등록하고 준비 보호가 끝난 뒤 해제한다. 기존 ended/published
코어 판정 및 원경험 저장소 수명은 유지했다. 원천 61개, 비동기 런타임 91개 검사 통과.
이는 캐시 관리의 전체 원천 순회 제거이며 전체 그래프의 디스크 적재·퇴거 완성이나
실측 지연 상한의 증거는 아니다.

Replay 후보 선택에서 후보마다 receipt 구간을 재탐색하고 InputMatch를 복제하던
경로를 제거했다. 고정된 구간을 순서대로 한 번 순회하며 모든 원경험 메타데이터를
기존 SWEGCA prefer_replay에 전달한다. 원문 읽기/할당/후보 생략 없이 기존 강도,
최근성, 주소 동률 규칙 및 개별 주소 범위 검사를 유지했다.
세션 런타임 1,151개, 런타임 생명주기 244개 검사 통과. 개별 핀과 구간이 섞인
44개 후보의 전역 선택 번호, 추가 기록 후 이전 receipt의 선택 보존, 선택 중
I/O·할당 0건을 확인했다. Replay 전체 원문 버퍼 및 구간 요청의 전체 체크섬 읽기는
변경하지 않았으며 전체 1ms/제한 메모리 운용 완료로 해석하지 않는다.

Main 정확 키 색인의 소유권을 각 ExperienceRouter에서 MainGraph로 옮겼다.
Main 병합 준비에서 새 cue 구간을 기존 context 구간과 함께 구성하고, 영속 발행 후
무할당 노드 이동으로 공개한다. 각 세션은 Main 포인터/head만 갱신하며, 연결 후보
목록과 전체 cue 색인을 복제하지 않는다. 이 복제의 증분 갱신에만 사용했던 파생
changed 목록도 제거했다. Main generation·병합 저널·root·셔플 결과 digest와
원경험 검증은 유지했다. 상세: MAIN_SHARED_CUE_INDEX.md.

Main 그래프 4,705개(할당 실패 지점 914개), 영속 Main 1,084개, 런타임 244개,
비동기 병합 91개, 실제 호스트 3,091개 검사 통과. 바뀐 Main head의 갱신과 두 번째
route의 최초 연결을 할당 허용 0 상태에서 확인했다. 이전 receipt의 세대 검증,
기록 보존, 불연속 cue 구간, 복구 후 원주소 Replay 및 활성 세션 우선 규칙을 유지했다.
Main 자체의 색인/경험 상주와 지역 디스크 적재·퇴거는 아직 남아 있다.

ExperiencePage 제한 크기 메타데이터 저장 단위를 추가했다. 검증된 ExperienceEvidence
입력으로만 생성되며 실제 쓰기 주소를 가진 핸들로 전체 체크섬과 SWEGCA admission을
확인한 후 단일 값 또는 전체 구간을 복원한다. 원경험 주소/출처/불확실성/관측/키를
보존하며 원문·강도·경험 수를 새로 만들지 않는다. 페이지 검사 1,557개 통과.
80,000바이트 단일 읽기 및 200,000바이트 전체 load 예산, 선택 밖 손상 거부를 확인했다.
중요한 미완료 경계: 현재 Main/ExperienceSequence 퇴거·적재에는 아직 연결하지 않았다.
다음 단계는 실제 구간 캐시 연결, 핀 수명, 영속 주소 소유권과 자원 회수다.

ExperiencePage를 ExperienceSequence의 봉인 구간 및 MainGraph의 명시적 page_out
호출에 연결했다. SWEGCA metadata_release가 완전 봉인/단독 소유/기존 backing
조건으로 유지·저장 후 해제·재해제를 결정한다. 핀/스냅샷/다른 연결이 공유한 구간과
부분 tail은 보호한다. 읽기 시 전체 체크섬/admission을 통과해 복원하고 동시 독자는
한 번만 적재 결과를 발행한다. Main 세대·강도·원주소는 바뀌지 않는다.

페이지/구간 1,595개, Main 4,713개, 세션 런타임 1,151개, 비동기 91개 검사 통과.
Main 퇴거 후 같은 원경험 Replay 및 backing 재사용, 적재 OOM 재시도, 공유/핀 보호와
동시 적재를 확인했다. 신규 자원 분기 단독 중앙값 1.78751ns 및 기존 코어 ns 측정은
benchmarks/results/core-metadata-residency.txt에 보존했다.
남은 연결: Runtime/서비스의 자동 예산 대응, 재시작 페이지 주소 복구와 공간 회수,
단일 대형 연결의 bounded 셔플. 이번 명시적 구간 경로를 전체 페이징 완료로 보지 않는다.

Runtime::page_out_main에 Main 구간 퇴거를 연결했다. 원경험 번호를 먼저 검증하고,
진행 중인 Main 준비/발행 작업이 있으면 파일 생성 전 거부한다. 동일 Runtime의
저장·I/O 예산을 페이지에도 적용하고 기존 페이지 이름은 덮어쓰지 않는다.
Runtime 265개, 비동기 94개 검사 통과. 핀 보호, 첫 쓰기 실패 뒤 같은 원주소 읽기,
퇴거의 메모리 감소, cold 상태의 무디스크 Recall 뒤 같은 원주소 Replay,
backing 재사용, 재시작 파일 크기 계수 및 원경험 기반 복구를 확인했다.
재시작은 파생 페이지 재사용이 아니라 기존 원경험/병합 저널 복구다.
명시적 소유자 호출까지 연결됐으며 자동 압력 대응, 페이지 회수, 큰 연결 셔플의
제한 메모리 운용과 전체 4GB/1ms 목표는 여전히 미완료다.

파생 ExperiencePage의 마지막 핸들 해제/이동 대입에 공간 회수를 연결했다.
SWEGCA discard_metadata_page가 소유 inode 일치·단독 링크 조건으로 허용하며,
VRS가 실제 파일 길이 일치와 unlink 성공을 확인한 뒤 fd를 닫고 저장 계수를 반환한다.
원경험 블록 소멸은 기존대로 원본 파일을 보존한다. 경로 교체·하드 링크·오류가 있으면
보수적으로 파일/계수를 유지한다. 실패한 생성 및 crash 잔여 파일의 회수는 아직 남는다.
페이지/구간 1,608개, Runtime 265개 검사 통과. 단독 코어 벤치의 회수 조건 중앙값
0.77831ns, 4축 판정 48.5789ns; 원자료 core-page-reclaim.txt. 디스크 삭제나 전체
입력 경로가 ns라는 의미는 아니다. 자동 메모리 압력 대응과 페이지 재시작 재사용,
대형 연결 셔플의 제한 메모리 운용, 전체 4GB/1ms 달성은 여전히 미완료다.

cold 경험 구간 복원의 임시 decoded vector 및 최종 배열 복제를 제거했다.

발행·종료 inventory를 공통 사용한다. 새 데이터베이스·판정식·이관은 없다.
파생 대조 결과는 독립 관측으로 세지 않아 original_count/강도 갱신에 재투입되지
않는다. 두 revision의 재시작/종료 후 조회, 최초 기록 불변, 중복 저장 용량 불변,
위조 주소·잘못된 revision·빈/과대 결과·종료 후 쓰기 거절을 포함해 세션 394개와

발행과 revision 조회 경로 연결은 다음 구현으로 남아 있다.

입력 기록은 덮어쓰지 않고, snapshot 저장 완료 뒤에만 완료 플래그를 세운다.
미저장 snapshot은 기본 전체 Replay 재시도 시 저장 경로를 다시 거친다.

호출자가 재시작 후 같은 결과를 정확히 조회할 수 있다. 입력 결합과 해시를
검증하며 조회 자체는 새 판단이나 Re-evidence 권한을 생성하지 않는다.
실제 stdio 3,653개 통과: 자동 응답의 seed7/step3, 명시적 seed19/step5 기록,

종료 세션의 호스트 조회 경로와 모든 수동 후보 대조 영속화는 아직 남는다.

수정 전 종료 직후 조회 거절을 재현했고, 수정 후 종료 직후·병합 후·재시작 후
내용 일치, 타 활성 세션 입력 유지, unknown source/위조 주소/복수 locator 거절,

새 판단을 수행하지 않는다. 최신 revision 자동 탐색과 수동 후보 전체 이력은 남는다.


native 세션의 수동 후보 전체 Replay 대조도 revision 저장에 연결했다. 이미
인증된 선택 원경험에 기존 core compare/Re-evidence를 적용한 실제 응답을 원입력,
sourceSession, selectedOriginal, seed/step과 함께 저장한다. 저장 성공 뒤 반환하는
revision으로 종료·병합·재시작 후 정확히 조회한다. 자동 선택 상태를 바꾸거나
저장 성공을 support/refute로 승격하지 않으며 충돌일 때만 Re-evidence를 유지한다.
동일 수동 대조 재시도의 결과/용량 불변, 초기 대조와 독립 보존, 부분 읽기 이후
대조 거절, 재시작 후 기록 일치를 포함해 stdio 3,755개 검사 통과. 기존 64KiB
metadata 상한과 큰 currentOriginals 목록 처리, 최신 revision 자동 탐색은 남는다.

실제 읽기 할당은 기존 공유 PMR 예산을 사용한다. 기록을 자르거나 주소 목록을
버리지 않고 저장·조회·종료 inventory에 같은 기준을 적용한다. 원문 형식 이관은
없고 초과 입력은 해시/쓰기 전에 거절한다. 131,073바이트 revision의 저장·재시작
일치, 메모리 소진 시 읽기 거절/해제 후 재시도, 상한 초과 거절을 포함해 세션
399개 및 stdio 3,755개 검사 통과. 주소 목록과 JSON 전체 materialization 비용은
남으며 전체 프로세스 4GB 검증이나 무한 크기 streaming 지원으로 해석하지 않는다.


최신 발행 cognition revision의 영속 별칭을 구현했다. SessionStore의 기존 core
append 허가 후 불변 결과를 먼저 봉인하고, 같은 inode의 임시 hard link를
원입력 키 위치로 rename·디렉터리 fsync하여 발행한다. 새 판정·시간순 추측·
메타데이터 삭제는 없다. 같은 현재 결과는 그대로 재사용하고 이전 결과를 명시적으로
재발행하면 물리 payload 중복 없이 그것이 최신이 된다. 최신 별칭도 종료 inventory에
포함하며 조회 시 원입력·결과 해시 결합을 검증한다. Host latest:true는 특정revision과
동시 지정할 수 없고, 저장된 별칭에서 digest를 복원하여 결과와 함께 반환한다.
세션 408개, stdio 3,771개 통과: 재발행 시 storage bytes 불변, 재시작/종료 후 최신
일치, staging 미채택, 종료 후 최신 디렉터리 누락 검출, 재시작 후 client가 digest를
주지 않은 최신 조회, malformed/conflicting selector 거절을 확인했다. 최신 참조는

cognition 발행 재시도의 동기화 누락을 실제 syscall 오류 주입으로 재현·수정했다.

셔플용 cold metadata 순회의 반복 읽기를 줄였다. 기존 Reader의 한 페이지 캐시는
