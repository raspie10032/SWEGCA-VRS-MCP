# VRS 메모리 계수

사용자 확정 사항: 메모리 사용량 계수와 한도 판단은 VRS 운용 계층이 소유한다.
SWEGCA 코어에 4GB 고정 제한을 넣지 않으며, 더 많은 자원을 쓰는 설정도 허용한다.

`cpp/vrs/memory_budget.hpp`의 `MemoryBudget`이 그 운용 계수를 제공한다.
Main이 VRS 인스턴스의 공통 예산을 하나 소유하고 해당 인스턴스의 할당 경로들이 공유한다.
이 객체는 `std::pmr::memory_resource`를 구현하며 자체 증거 판정이나 메모리 의미 판정을 하지 않는다.

## 계수와 제한

- `limit()`은 Main이 생성할 때 지정한 바이트 수다. 4GB 상한 상수는 없다.
- `used()`는 현재 예약된 요청 바이트 합계다. 해제를 마친 뒤 사용량을 반환한다.
- `peak_reserved()`는 예약량의 최고값이다. 기반 할당자가 나중에 실패한 일시 예약도 포함한다.
- 원자적 예약으로 여러 작업자가 동시에 호출해도 한도를 초과하지 않는다.
- 한도 초과나 기반 할당 실패는 `std::bad_alloc`이다. 실패한 예약은 반환한다.
- 0바이트 요청도 최소 1바이트의 예약을 소비한다. 크기 덧셈의 오버플로 전에 한도를 검사한다.
- 정렬 요구를 기반 할당자에 전달한다. 기반 할당자는 여러 작업자가 공유할 경우 스레드 안전해야 한다.

이는 **이 자원을 통과하는 할당의 요청 바이트 계수**다. 할당자 메타데이터, OS 페이지 캐시,
스레드 스택, 현재 다른 할당 경로와 프로세스 코드까지 합친 RSS라고 주장하지 않는다.
4GB 환경의 완성된 VRS 검증에는 남은 동적 자료구조 연결과 실제 프로세스 계측이 필요하다.

## 원경험 읽기 연결

```cpp
swegca::vrs::MemoryBudget memory(4'000'000'000ULL);
// memory는 반환된 경험들을 모두 해제할 때까지 살아 있어야 한다.
auto experience = block.read(location, per_record_limit, memory);
auto original = experience.view();
```

`StoredExperience`의 본문은 이 자원을 사용하는 `std::pmr::vector`에 보관한다.
텍스트·본문 뷰는 이 버퍼를 가리키며 추가 복사를 만들지 않는다. 반환 객체는 이동 생성이
가능하고 복사와 이동 대입은 제공하지 않는다. 이를 통해 다른 기본 할당자로 복사되거나
서로 다른 예산의 객체에 대입되는 경로를 만들지 않는다.

예산을 넘어선 읽기는 새 버퍼를 만들지 못하며 이미 보관한 경험을 훼손하지 않는다.
해시 검사 등 읽기 중 오류가 난 경우에도 객체 소멸로 사용량을 반환한다.

## 검사

- `tests/memory_budget_tests.cpp`: 31개 확인, 두 스레드의 예약 경쟁 2,000회.
- 정해진 총량 안에서 여러 할당, 초과·정수 최대값 거부, 기반 할당 실패 후 복원,
  0바이트 처리, 정렬, 4GB보다 큰 설정을 확인한다.
- 큰 설정 검사는 8GiB 한도를 허용하는지만 확인하며 실제로는 1바이트를 할당한다.
  대규모 실제 메모리 사용 검증으로 보고하지 않는다.
- 원경험 블록 검사는 실제 읽기 두 건의 합산 제한, 첫 객체 해제 후 읽기 재개,
  이동 시 추가 할당 없음, 손상된 기록의 실패 후 계수 반환을 확인한다.

코어 판정 함수의 실행 경로에는 이 할당자를 넣지 않았다. 판단 공정의 ns 요구와
VRS의 원경험 읽기 버퍼 관리를 각 소유 계층에서 검증한다.
