# 연결 판정 이력과 강도의 영속 복구

2026-09-26. `PersistentConnection`은 기록된 원경험을 셔플해 코어로 검증하는 기존 경로에
영속 기록을 연결한다. 초기 강도는 Main이 명시적으로 전달하며 기본값을 새로 정하지 않는다.

## 기록과 상태 반영

```text
append:
  원경험 주소 선택 읽기 → 실제 관측값 복원 → 코어 입력 검사와 메모리 준비
  → 원경험 주소와 전후 개정을 영속 기록 → 해당 연결에 관측값 반영

refine:
  실제 관측값 셔플 → SWEGCA 판정·강도 계산
  → 입력·판정·강도·계보를 영속 기록 → 해당 연결의 강도·개정 반영
```

`Connection`의 준비와 반영 함수는 private이다. 공개된 임의 판정 적용 API는 추가하지 않았다.
단일 소유자가 순차 호출한다는 계약 아래 반영 단계에는 할당이나 I/O가 없다.
준비·기록이 실패하면 연결의 강도·개정·경험 내용·헤드 주소가 유지된다.
메모리 준비에서 확보한 벡터 용량은 남을 수 있으며 VRS 예산에 계속 계수된다.

영속 기록은 현재 세션의 원경험 블록을 사용한다. 따라서 세션 코어가 종료된 세션의 새 기록을
거부하면 연결 갱신도 반영되지 않는다. 외부 DB, SQLite, 호환 이관 코드는 사용하지 않는다.

## 불변 기록

`SWGCCON1` 본문에 다음 세 종류를 기록한다.

- 시작: 연결 ID, Main이 지정한 초기 강도, 실제 `EvidencePolicy`의 모든 수치.
- 관측 추가: 직전 기록 주소, 연결 ID, 기록 순번, 전후 개정, 원경험 주소.
- 셔플 검증: 직전 기록 주소, 연결 ID, 기록 순번, 전후 개정, 셔플 시드·검증 시점,
  이전·다음 강도와 전체 계산 결과의 다이제스트.

다이제스트에는 검증 입력 집계, 코어 판정과 사유·수치, 강도 결과, 실제 셔플 방문 순서와
경험별 수용 사유를 포함한다. 부모 주소가 이전 관측 추가 기록과 실제 원경험 주소를 잇는다.
모든 정수는 little-endian, 부동소수점은 binary64 비트를 기록하며 구조체 패딩을 저장하지 않는다.

고정 헤더는 152바이트다. 종류에 따라 전체 본문은 시작 236, 추가 232, 셔플 검증 216바이트다.
생성한 데이터의 체크섬은 기존 원경험 블록이 검증한다. 외부에서 읽은 기록은 이 길이와
예약 영역, 메타데이터, 연결 ID, 부모 계보, 순번과 개정을 검사한다.

## 복구

Main이 가진 **연결의 마지막 기록 주소**를 입력받아 그 부모 계보만 읽는다.
원문 전체에서 최신처럼 보이는 항목을 검색하지 않는다.
원래 규칙과 초기 강도를 복원하고, 관측 추가마다 기록된 원경험을 선택해서 읽는다.
각 셔플 검증을 SWEGCA로 다시 실행해 판정 다이제스트와 수치가 비트 단위로 일치하는지 확인한다.

기록 자체 체크섬이 유효해도 저장된 강도·시드·개정·판정 내용이 재실행 결과와 다르면 복구를 거부한다.
종료되거나 공개된 세션도 읽기 복구가 가능하지만 그 세션에 새 결과를 기록할 수 없다.
복구 과정은 새 영속 기록을 만들지 않는다.

복구용 이력은 초기 상태 재구성에 사용한다. 사용자 자연 입력의 Déjà vu·Recall·Replay·Re-evidence
경로는 별도로 남아 있으며, 이력 재실행 시간을 Recall 지연으로 보고하지 않는다.

## 현재 통합 경계

- Main이 제공한 마지막 주소에서 연결을 복구하는 구성요소까지 구현했다.
- **어느 헤드가 최신인지 결정·발행하는 Main 루트, 연결별 소유자 등록, 변경 전 루트 대조와
  세션 간 병합은 아직 미구현이다.** 이 API가 최신 헤드를 자동 선택하지 않는다.
- 옛 주소를 지정하면 그 역사적 버전을 복원한다. 이를 현재 권위 상태로 올릴 권한은 이 API에 없다.
- 현재 원경험 주소의 읽기는 같은 `SessionStore` 범위다. 임시·메인을 잇는 주소 해결은 남아 있다.
- 기록 주기를 처음부터 다시 계산하므로 긴 계보 복구에 대한 체크포인트 최적화는 남아 있다.
- 일반 대화에서 검증 관측을 만드는 처리, 전체 경험 그래프, 기억 4단계와 운영 자원 제한도 남아 있다.

## 검증

- 전체 `make -j2 check` 통과: 기존 코어 3,951, VRS 36, 블록 88, 메모리 31과 경쟁 2,000회,
  연결 1,436, 세션 169, 영속 연결 검사 및 컴파일 계약 15개. 새 검사는 이후 경계 사례를
  확장한 최종 **65회**가 일반 빌드와 UBSan trap 구성에서 모두 통과했다.
- 승인→강화 후 재시작, 만료된 지지와 새 반증→약화 후 재시작을 검사했다.
- 증거 없음의 무효 기권과 부족한 증거의 유효 기권을 구별해 복원하고 `-0.0` 비트를 보존했다.
- 축 수·확신도·사전값·최근 창을 바꾼 정책을 원래 비트대로 복원했다.
- 다른 연결의 관측 추가와, 복구 기록을 관측값으로 넣는 요청을 거부했다.
- 저장 강도·다이제스트·시드·연결 ID·순번·개정·예약 바이트 및 잘린 본문을 변조한
  유효 체크섬 레코드를 복구 시 거부했다.
- 테스트 실행파일에만 연결한 `pwrite` 오류 주입으로 실제 부분 기록 뒤 `ENOSPC`를 발생시켰다.
  연결의 강도·개정·헤드는 유지됐고, 기존 헤드에서 복구해 새 블록에 이어 쓰는 것을 확인했다.
- 종료된 세션에서 갱신을 시도하면 새 연결 상태와 기록 수 모두 바뀌지 않았다.

실제 전원 차단 시험은 수행하지 않았다. 코어 판정식과 강도 연산은 변경하지 않았으며,
이번 파일 기록·복구 경로의 지연을 ns 코어 연산 측정으로 대체하지 않는다.
