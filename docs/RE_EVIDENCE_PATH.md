# Replay 이후의 현재 관측 검증

2026-09-26. 자연 입력의 `InputRecall`을 Replay하면 `ReplayedInput`이 발행된다.
이 객체는 실제 읽은 원경험, 당시 연결 헤드, 임시 세션의 관측 개수 경계를 보존한다.
외부에서 원경험이나 이전 판정을 넣어 객체를 만들 수 없다.

## 연결한 실행 순서

1. `input`은 Déjà vu 키와 Recall 주소를 만든다. 후보마다 그 시점의 임시 관측 개수를 기록한다.
2. `replay`는 선택한 헤드의 일치 여부를 검사하고 원경험 한 건을 읽는다.
3. 이후 실제 관측값은 기존 `SessionRuntime::observe`를 통해 임시 경험에 반영한다.
4. 추가 검증이 필요한 Main 호출 경로에서 `re_evidence`에 Replay 객체를 전달한다.
5. 같은 연결에 Recall 이후 추가된 관측값만 새 셔플 입력으로 구성해 SWEGCA 코어로 검증한다.
6. SWEGCA `compare_replay_evidence`가 같은 명제의 과거 관측과 현재 판정의 일치·반대를 비교한다.

이것은 기록된 관측값의 경로다. 원문의 일치나 연속 문맥을 현재 사실의 승인으로 바꾸지 않는다.
불충분·만료된 과거 관측, 현재 기권, 현재 관측 부재는 불충분으로 남는다.
현재 지지/반박의 판정은 기존 SWEGCA 검증 함수가 수행한다. 대조 함수가 그 판정을 덮어쓰지 않는다.

## 자기 확인과 중복 갱신 방지

- Recall 이전에 있던 임시 관측을 현재 요청의 새 관측으로 다시 계산하지 않는다.
- 메인에서 Replay한 원경험을 현재 관측 집합에 자동으로 넣지 않는다.
- 다음 Recall은 새 경계를 설정하므로 이전 요청에서 이미 있었던 관측은 다음 요청의 새 집합에서 제외된다.
- Re-evidence는 읽기 전용 계산이다. 이미 `observe`에서 반영한 강도를 두 번째로 갱신하지 않는다.
- 결과에는 자연 입력의 내용 주소, 선택 원경험 주소, 과거·현재 연결 헤드, 현재 관측 원경험 주소 목록과 셔플 판정이 함께 남는다.
- 다른 입력 라우터가 만든 Recall/Replay 객체는 거부한다.

경계는 **이 임시 세션에 기록된 순서**다. 실제 외부 관측의 진실성이나 수집 시각을 저장 순서만으로
증명하지 않는다. 출처·문맥·생산자·만료·중복 처리는 기존 SWEGCA 규칙을 그대로 적용한다.

## 아직 남은 범위

일반 문장의 의미 대조, Re-evidence가 필요한지 결정하는 전체 Main 처리 경로, durable activation
receipt 발행 및 세션 간 그래프 병합은 미완료다. 이 결과는 semantic/action/write 권한을 발행하지 않는다.
프로세스 재시작 이후 진행 중인 요청을 그대로 재개하는 경로도 아직 연결하지 않았다.

## 확인

- 현재 런타임 검사 234회와 같은 검사의 UBSan trap 실행을 통과했다.
- 새 지지·반박·불충분·만료 관측을 각각 추가해 현재 코어 판정과 과거 관측 대조를 확인했다.
- 새 관측이 없을 때 과거 메인 경험을 현재 근거로 가져오지 않음을 확인했다.
- 다음 Recall부터는 앞서 있던 관측이 새 근거 집합에서 제외됨을 확인했다.
- Re-evidence 동안 파일 읽기·쓰기와 기존 연결 강도·헤드 변경이 없음을 확인했다.
- 원래 입력 키, 선택 원경험 주소, 과거·현재 헤드와 현재 관측 주소가 결과에 결합됨을 확인했다.
- 다른 라우터의 Recall/Replay를 거부하고, 모든 결과 해제 뒤 공유 할당 사용량이 0임을 확인했다.
- 비교 코어 함수는 2.81393ns였다. CPU 6, GCC 16.2.1, `-O3 -ffp-contract=off`,
  100,000회 예열 후 100,000회 호출씩 31묶음 평균의 중앙값이다. 같은 측정에서 4축 코어 판정은
  44.3674ns였다. 전체 Re-evidence 계산이나 입력→Recall 지연의 측정은 아니다.
