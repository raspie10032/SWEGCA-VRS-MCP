# 세션 중 기록과 종료 후 원경험 공개

2026-09-26. `SessionStore`는 Main이 소유하는 세션별 원경험 저장 구성요소다.
사용자 지시인 “세션 중에는 임시, 메인에는 세션 종료 후”를 상태 전이와 물리 저장에 적용한다.

## 코어의 상태 전이

`session_kernel.hpp`에 사용자 지시를 순수 코어 연산으로 두었다.

| 상태 | 작업 | 결과 |
| --- | --- | --- |
| active | 기록 | active |
| active | 명시적 종료 | ended |
| ended | 원경험 공개 | published |
| 그 외 조합 | 요청 | 거부, 출력 상태 invalid |

유휴 시간, 대화 공백, 타이머를 종료로 처리하는 경로는 없다.
파일 작업이 성공하고 동기화된 뒤에만 객체가 다음 상태로 진행한다.
종료된 세션에는 새 원경험을 추가할 수 없다.

## 기록·분할·선택 읽기

- 세션의 사용자·어시스턴트·도구 등 원문은 출처와 미디어 타입, 시점, 원래 바이트를 보존한다.
- 관측 결과가 있는 경험은 기존 `record_evidence` 경로를 통해 관측값과 원문을 함께 기록한다.
- 설정한 물리 블록에 기록이 더 들어가지 않으면 다음 블록을 만들고 주소를 반환한다.
- 읽기는 요청된 원경험 주소가 속한 세션 블록 하나를 연 뒤 그 레코드만 읽는다.
- 서로 다른 세션은 독립적으로 기록할 수 있고 VRS 메모리 예산을 공유한다.
- 세션 제어 블록의 파일 잠금으로 같은 세션에 두 쓰기 소유자가 생기는 것을 막는다.

현재 한 레코드 자체가 블록보다 크면 잘라내지 않고 오류를 반환한다. 한 원경험을 여러
블록 조각으로 스트리밍하는 기능은 남아 있다. 블록 분할이 전체 경험 그래프의 region·portal
연결을 구현한 것은 아니다.

## 종료와 공개의 영속성

종료 시 세션 ID, 블록 용량, 원경험 수, 블록 수와 블록별 내용 다이제스트를 묶는다.
내용 다이제스트는 기록이 동기화될 때 원경험의 체크섬·주소를 순서대로 누적한다.
종료 시 원문 본문을 다시 읽지 않는다. 재시작 복구 시 검증된 각 레코드로 같은 값을 재구성한다.

완료된 종료 기록을 `closed.block` 이름으로 공개하고 디렉터리를 동기화한다.
미완료 `ending-N.block` 파일은 유지하며 종료로 인정하지 않는다.
다음 종료 요청은 새 파일을 사용한다.

`publish_originals()`는 종료 기록을 확인한 상태에서 동일 파일시스템의 `main/` 아래에
하드 링크를 발행한다. 원문은 복사하거나 이동하지 않으므로 기존 원경험 주소가 유지된다.
메인에 공개되는 것은 종료된 원경험 묶음의 위치다. **연결 강도와 그래프의 통합 병합,
진행 중 검증 작업과의 동기화, 의미기억·행동 권한 발행은 아직 이 경로에 연결되지 않았다.**

공개 후에도 기록들이 가진 검증·기권·반증 상태가 공개 자체로 승격되지 않는다.
현재 원경험 공개 API를 전체 VRS 병합 완료로 취급하지 않는다.

## 복구

- 원경험 본문의 완성된 기록은 체크섬으로 검증한다.
- 마지막 불완전 기록은 삭제·잘라내지 않는다. 이어 쓰기는 새 블록을 사용한다.
- 종료 기록이 있으면 원경험 목록과 내용 다이제스트가 일치해야 종료 상태를 복구한다.
- 메인 공개 파일은 그 세션의 종료 기록과 동일한 inode여야 한다.
- 저장 I/O 실패 후에는 해당 소유자의 추가 변경을 거부하고, 다시 열어 디스크 상태를 확인한다.

현재 세션을 다시 열 때는 원경험 블록을 검사한다. 큰 메인 전체를 매 조회마다 여는 경로는
아직 없다. 대규모 재시작용 체크포인트·색인과 전체 메인 조회는 계속 구현해야 한다.
실제 전원 차단 시험은 수행하지 않았다. 아래 증거는 로컬 파일·불완전 기록 경계 검사다.

## 검증

- `make -j2 check`: 세션 169회 확인 및 기존 코어·VRS·블록·메모리·연결·컴파일 계약 통과.
- 새 세션 검사는 UBSan trap 구성에서도 169회 통과했다.
- 종료 전 공개 거부, 종료 후 추가 기록 거부, active/ended/published 재시작 복구를 확인했다.
- 여러 물리 블록과 바이너리 원문·NUL·출처를 보존하고 공개 전후 원문 파일 수·용량·주소를 확인했다.
- 임시 세션에 관측값 기록 → 선택 읽기 → 셔플 → 코어 승인 → 해당 연결 강도 갱신을 검사했다.
- 기존 공개 세션의 원문을 새 임시 세션이 있는 동안 읽었다. 임시 우선 자동 검색은 아직 미구현이다.
- 불완전 원경험 꼬리와 종료 준비 파일을 유지한 채 복구를 확인했다.
- 길이·기록 수는 같고 레코드 자체 체크섬도 유효하지만 내용이 바뀐 파일은 종료 목록 대조에서 거부했다.
- 두 세션을 두 스레드에서 동시에 기록·종료·공개했고, 사용한 계수 대상 메모리가 해제됐음을 확인했다.

## 코어 시간과 운영 범위

CPU 6 고정, GCC 16.2.1, `-O3 -march=native -ffp-contract=off`, 100,000회 예열 후
100,000회 호출 묶음 31개의 평균 중앙값: 세션 상태 전이 **1.26872ns**.
동시에 다른 CPU에서 UBSan 빌드·검사를 진행했고 Palworld를 계속 실행했다.
이 수치는 파일 동기화 시간이나 사용자 입력→Recall 지연을 포함하지 않는다.
측정 원문은 `measurements/session-transition-20260926.txt`에 보존했다.

대화 수집 훅, 원문 전체의 VRS 경험 처리, 임시 우선 검색, 기억 4단계, 그래프·강도 병합,
4GB 전체 RSS·5Gbps I/O·500GB 저장량 통제는 남은 작업이다.
