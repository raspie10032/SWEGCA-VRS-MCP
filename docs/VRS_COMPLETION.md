# SWEGCA 기반 VRS C++ 완결 작업

2026-09-26 사용자 승인으로 장기목표 등록. 브랜치: `codex/vrs-completion-20260926`.

## 절대 준수

- 모든 VRS 절차의 결정은 SWEGCA 코어를 논리소자로 조합해서 구현한다.
- 이미 보강한 코어의 판정식과 수치 순서를 유지하며 코어 한 공정은 ns 시간대를 유지한다.
- 폐기된 C++ VRS와 후보 설계 문서, SQLite, Hermes, 외부 대체 판정 로직, 프리빌트 휠을 사용하지 않는다.
- 새 경험의 셔플된 값으로 검증한다. 과거 집계의 방문 순서만 바꾸는 구현으로 대신하지 않는다.
- 승인/반려/기권을 강화/약화/유지에 대응시키고 원경험·출처·불확실성·반증을 보존한다.
- 사용자 입력 즉시 Déjà vu → Recall → 선택 원경험 Replay → 불일치 시 Re-evidence.
  입력부터 Recall까지 1ms 미만을 실제 경로에서 검증한다. 앞에 셔플이나 병합을 넣지 않는다.
- 세션 전체 내용을 실시간 임시 경험으로 반영한다. 조회는 임시 우선, 찾지 못하면 메인.
  메인 병합은 세션 종료 후 수행한다.
- 경험 분할·연결선·병렬 처리, 4GB 메모리·5Gbps SSD·500GB 저장 조건을 VRS 계층에서 다룬다.
  더 큰 자원 설정도 허용한다. 코어에 운용 자원 한도를 고정하지 않는다.
- Main이 상태와 권한을 소유한다. 실시간 내부 LLM 호출은 0회다.
- Claude 통신은 중지 상태를 유지한다. Palworld 실행 자원을 남기고 빌드 병렬도는 2로 둔다.
- GitHub Actions를 실행하지 않는다. 현재 저장소는 원격 주소가 없어 로컬 커밋으로 작업을 보존한다.

## 이번 구현의 경계

`connection_strength_kernel.hpp`는 보존 코어를 다시 작성하지 않고, 사용자 지정 원본의
강도 연산을 코어 논리소자로 추가한 것이다. 판정은 기존 `judge_evidence`가 수행한다.
강도 계산과 검증 경험 자격은 이 코어 함수의 출력으로 전달한다.

입력 강도가 유한한 비음수가 아니거나 코어 입력이 무효이거나 곱셈이 넘치면 결과는 무효다.
큰 값을 임의로 잘라내거나 판정을 바꾸지 않는다. 초기 강도도 임의 기본값을 만들지 않고
호출자가 소유한 기존 강도를 받는다. 기권인 경우 강도는 그대로 유지한다.

수정 가능한 상태와 영속 반영은 Main의 책임이다. 코어 함수의 `valid()`나 강도 ≥1.0만으로
영속 쓰기나 외부 행동을 허용하지 않는다.

## 첫 구현 묶음의 확인

- `make -j2 check`: 코어 3,951회 확인, VRS 36회 확인, 컴파일 계약 15개 통과.
- VRS 검사는 정상 3상·무효 입력 매핑, 복사/대입 일관성, 강도 갱신과 1.0 경계,
  NaN/Inf/음수/넘침 처리, 무효 결과로 대입한 뒤 이전 성공이 남지 않는 것을 확인한다.
- 컴파일 계약은 판정과 방향을 따로 변경하거나 모순된 결과를 직접 생성할 수 없음을 확인한다.
- CPU 6에 고정한 한 스레드 측정, GCC 16.2.1, `-O3 -march=native -ffp-contract=off`:
  연결 강도 연산 1.33461ns, 4축 판정+강도 연산 50.4906ns.
- 100,000회 예열 후 100,000회 호출 묶음 31개 평균의 중앙값이다. 개별 호출의 최대 지연,
  완성된 VRS 성능 또는 이전 측정 대비 속도 향상을 주장하는 수치는 아니다.
- 실제 경험에서 판정 입력을 만드는 부분과 영속 연결 갱신은 아직 미완료다.
