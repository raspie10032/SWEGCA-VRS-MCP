# Replay 맥락을 통한 임시 연결 조회

기존 정확 cue와 직전 연결 ID에 더해, 성공한 Replay의 봉인된 관측에 기록된
`context` 식별자로 임시 VRS의 다른 연결을 찾는 경로를 추가했다.

## 코어 조회 순서

입력의 Déjà vu 키를 계산한 뒤 코어 `familiarity_key`가 다음 우선순위를 적용한다.

1. 임시 VRS의 정확 cue
2. 임시 VRS에 존재하는 직전 Replay 연결
3. 두 경로가 없으면, 직전 Replay와 같은 context를 가진 임시 경험
4. 임시 결과가 없을 때 기존 Main 조회

정확 cue나 직전 연결이 있으면 context 색인을 조회하지 않는다. 코어의 기존 임시
우선 정책을 유지하므로, context로 발견한 임시 경험도 Main보다 우선한다. 이 결과는
조회 후보이며 현재 발언의 진실성·행동 권한·연결 강화 근거가 아니다.

## 생성·보존 경계

- context 키는 선택 원경험의 전체 Replay가 성공하고 주소 검증을 통과한 뒤에만
  저장한다. 부분 읽기, 실패한 Replay, 원문 유사도 또는 모델 발화로 만들지 않는다.
- SessionRuntime은 커밋된 연결의 봉인된 관측에서 context→원경험 참조를 구성한다.
  새 경험도 기존 저장·셔플·코어 검증·catalog 발행 후에 이 색인에 노출한다.
- 색인용 공간은 영속 변경 전에 예약한다. 재시작 시 검증된 연결 이력으로 재구성한다.
- context 후보는 `(연결 ID, 원경험 번호)` 순서를 유지한다. 실시간 기록과 복구가
  같은 순서를 사용한다. 원문·관측을 복제하거나 새로운 증거 표본으로 세지 않는다.
- 위 참조 색인은 **임시 세션**에 적용된다. 아래 Main 맥락 포털은 별도의 Main 소유
  구간 색인을 사용한다. 같은 digest라는 기록된 관계 외의 의미를 추정하지 않는다.

## 검증과 비용

세션 Runtime 검사 515개, 영속 Main 검사 1,076개, MCP 검사 2,213개가 통과했다.
새 사례는 Main의 원경험 Replay 후 다른 임시 연결 두 개로 이어지는 경로, 관계없는
맥락 제외, 정확 cue 우선, 부분/실패 Replay의 키 생성 금지, 조회 중 pread/pwrite 없음,
Replay에 의한 강도 불변, 재시작 후 동일 순서를 검사한다.

추가 context 색인은 메모리를 사용한다. 현재 참조 하나는 64비트 실행 환경에서
32바이트 연결 ID와 8바이트 원경험 번호이며 vector 여유 용량과 context별 트리 노드가
별도로 필요하다. 이는 전체 4GB 운용 완료를 뜻하지 않는다. 조회는 경험 원문을 읽지
않지만 후보를 많이 찾으면 receipt 생성 비용이 증가한다. 지역별 제한·디스크 적재와
실제 앱 입력 지연 검증은 계속 남아 있다.

## Main의 기록된 맥락 포털

MainGraph가 `context → (연결 ID, 원경험 구간)` 색인을 소유한다. 활성 라우터마다
이를 복제하지 않는다. 명시적으로 종료·발행된 세션을 병합할 때 새 봉인 관측으로부터
구간을 준비한다. 같은 연결의 인접한 맥락 구간은 합치며, 원경험이나 검증 표본을
복제하지 않는다. 준비 중 할당 실패는 기존 공개 그래프를 바꾸지 않고, 영속 병합 기록
뒤 확정 단계에서는 준비된 노드를 이동한다.

Main 조회에서 정확 cue가 없고, 성공한 Replay의 context가 **서로 다른 연결**을
가리키면 코어가 context 경로를 선택한다. 연결 하나에만 있는 context는 기존 직전
연결 조회를 대체하지 않는다. 임시 VRS 우선 규칙과 정확 cue 우선 규칙은 유지한다.
후보는 기존 연결 지역 디렉터리를 통해 찾고, 선택 원경험만 Replay한다. 기록된 맥락의
일치는 조회 관계이며 지지·반박·진실·행동 권한의 증거가 아니다.

이 색인은 원본 관측과 검증된 병합 이력에서 재구성된다. 별도 외부 데이터베이스나
포털 판정기를 추가하지 않았다. Main 세대가 바뀌면 오래된 Recall은 기존 규칙으로
거부되며, 라우터를 갱신한 후 새 맥락 구간을 조회한다.

검증: Main 그래프 4,715개(916개 할당 실패 지점 포함), 영속 Main 1,089개,
세션 Runtime 515개, MCP 2,213개 통과. 257개 연결/두 주소 지역의 재시작 후 서로
다른 지역에 있는 두 맥락 연결을 조회·Replay했다. 추가 병합 후 후보가 세 개로
늘어나는 것, 이전 receipt 거부, 원문 읽기 없이 조회, 강도 불변을 확인했다.
코어 familiarity 분기는 CPU 6의 2,000,000회 단독 측정에서 평균 1.132ns/call이었다.
전체 입력→Recall 1ms 달성의 증거는 아니다.

남은 한계: 이 기능은 **기록된 context 관계를 통한 Main 조회**다. 자연어 의미로
맥락을 새로 판별하거나, 동일 원경험을 여러 가설에 공유하는 전체 그래프를 완성한
것은 아니다. context 구간 수에 비례하는 메모리가 추가되며, 디스크 퇴거·적재와
전체 4GB 운용 검증도 남아 있다. 별도 SessionRuntime들을 직접 mount하는 예전
호출 방식은 기존 조회를 유지하고, Main 포털은 실제 PersistentMainGraph 경로에 적용된다.
