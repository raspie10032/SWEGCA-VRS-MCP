# VRS 원경험 블록

SWEGCA의 원경험 가용성·출처 보존 규칙을 위한 물리 저장 구성요소다.
판정은 SWEGCA 코어, 경험의 선택과 상태·권한은 Main이 소유한다. 블록에 기록되었거나
읽혔다는 사실에서 승인·신뢰도·쓰기 권한을 만들지 않는다.

## 원경험과 주소

`OriginalExperienceView`는 세션, 출처, 매체 종류, 세션 내 순서, 관측 시각과 원문 바이트를
그대로 받는다. UTF-8 문자열만으로 제한하지 않으며 NUL과 바이너리 내용도 보존한다.
출처와 매체 정보가 없는 호출은 오류로 돌려보낸다. 상위 입력 경로는 그 오류를 처리해야 한다.

`append`는 전체 기록의 `fdatasync`가 성공한 뒤에만 주소를 반환한다. 주소는 블록 정체성,
시작 위치, 길이, 내용 해시로 구성된다. `read`는 그 주소에 해당하는 기록만 읽고 검증한다.
원경험 선택이나 의미 검색을 이 파일에서 수행하지 않는다.

이 클래스는 원경험 본문의 저장 구성요소다. 대화 내용을 SWEGCA 입력으로 만들거나 연결을
강화하는 고수준 경험 반영 경로는 별도 미완료 항목이며 저장 성공으로 대체하지 않는다.

## 형식

모든 정수는 unsigned 64-bit little-endian이다. 호스트의 구조체 정렬을 파일에 쓰지 않는다.

| 구성 | 바이트 | 내용 |
| --- | ---: | --- |
| 블록 헤더 | 80 | `SWGCBLK1`, Main이 부여한 32바이트 블록 정체성, 블록 용량, 앞 48바이트의 SHA-256 |
| 기록 접두부 | 64 | `SWGCEXP1`, 총 길이, 순서, 관측 시각, 세션·출처·매체·본문의 길이 |
| 기록 본문 | 가변 | 세션, 출처, 매체 종류, 원경험 본문 바이트 |
| 기록 끝 | 48 | 접두부+본문의 SHA-256, `SWGCEND1`, 총 길이 반복 |

SHA-256은 보존된 SWEGCA C++ 구현을 사용한다. 내용·위치 검증을 위한 값이며 권한 토큰이
아니다. 주소를 보관하는 Main의 경험 구조와 출처 연결은 별도 소유 책임이다.

## 크기와 동시성

- 블록 용량은 Main이 지정한다. 기록이 남은 공간을 넘으면 쓰기 전에 실패한다.
- 읽기는 호출자가 지정한 `max_read_bytes`와 Main이 소유한 공유 `MemoryBudget`을 모두 적용해
  한 기록의 인코딩 버퍼를 할당한다. 여러 읽기 결과를 보관하면 그 할당 크기를 합산한다.
  [계수 범위와 수명](VRS_MEMORY_BUDGET.md)을 따르며 전체 프로세스의 RSS 제한은 아직 미완료다.
- 복구 점검의 읽기 작업 버퍼는 64KiB이며 전체 블록을 RAM에 올리지 않는다.
- 블록별 쓰기 소유자는 하나다. OS 파일 잠금으로 두 번째 쓰기 핸들을 거부한다.
  읽기 핸들은 분리해서 사용한다. 서로 다른 블록의 작업은 독립적이다.
- 한 쓰기 객체에 대한 호출은 Main이 직렬화해야 한다. 호출 중 입력 뷰의 바이트는
  변경하면 안 된다. 전체 VRS 작업을 한 스레드로 직렬화하라는 뜻은 아니다.

## 불완전한 쓰기와 손상

일반 주소 읽기는 복구 순회를 실행하지 않는다. 쓰기 재개를 위해 파일을 열 때만 기존
기록을 순차 검증한다. 마지막 기록이 짧게 끝나면 완성된 앞부분과 불완전한 꼬리의 길이를
보고하고, 그 블록에서 추가 쓰기를 금지한다. 바이트를 지우거나 덮어쓰지 않는다.
상위 블록 관리자는 이 블록을 보존한 채 다음 블록을 사용해야 한다.

완전한 기록의 내용 해시나 종료 표식이 틀리면 손상 오류다. 이를 단순한 미완성 꼬리로
간주해서 무시하지 않는다. 이전 기록의 선택 읽기는 다른 기록 전체를 순회하지 않으므로,
후속 기록 하나가 손상돼도 선택한 정상 기록을 읽는 동작은 유지된다.

생성 시 파일을 동기화한 뒤 부모 디렉터리도 `fsync`한다. 기존 경로는 덮어쓰지 않는다.
쓰기 도중 I/O 오류가 나면 그 핸들의 추가 쓰기를 금지한다. OS/장치의 전원 장애 상황을
실제 실험한 결과는 아니며, 상위 주소 목록·세션 상태와의 원자적 발행은 아직 미구현이다.

## 확인한 범위

`tests/experience_block_tests.cpp`: 88개 확인 통과. Linux 로컬 파일에서 실제 쓰기·다시 열기·
주소 읽기·검증을 수행한다.

- UTF-8·NUL·100,000바이트 바이너리 본문과 출처 메타데이터 보존
- 재시작 후 이어 쓰기와 기존 주소 유지
- 두 번째 쓰기 소유자 거부, 읽기 전용 핸들의 쓰기 거부
- 용량 및 읽기 예산 초과, 주소·길이·내용 해시 불일치 거부
- 세 위치에서 마지막 쓰기가 끊긴 파일을 만들어 원본 바이트 보존과 읽기 경계 확인
- 완성된 내용 손상, 길이 필드 손상, 짧은 블록 헤더 탐지
- 손상된 후속 기록을 읽지 않고 이전 정상 기록만 선택해서 읽기
- 공유 메모리 예산 초과 시 거부, 해제 후 재사용, 실패한 읽기의 할당 반환
- 반환 객체 이동 시 추가 할당 없음. 복사에 따른 예산 우회를 방지
- UBSan trap 빌드에서도 같은 확인 통과

전체 실행: `make -j2 check`.
이는 원경험 저장 구성요소 검증이다. 세션 입력 훅·셔플값 변환·기억 4단계·메인 병합·
총 자원 제한 및 VRS 전체 지연 검증은 미완료다.
