# 셔플값의 SWEGCA 검증과 연결 갱신

2026-09-26. 브랜치 `codex/vrs-completion-20260926`.

사용자 정정: “셔플값을 스웨카가 검증해서 강화/약화/기권판정으로 하는 원리”.
이전 문서는 현재 집계형 함수 입력을 고정된 전제로 놓고 사용자에게 연결 정의를
다시 요구했다. 이는 구현의 빈 부분을 사용자 지시의 누락으로 취급한 잘못이다.
아래 원리는 확정됐으며, 현재 함수와 실제 경험 처리 사이의 연결은 구현 작업이다.

## 확정된 사용자 지시

블록 안의 경험을 섞고, 그 셔플값을 SWEGCA로 검증해 승인/반려/기권을
연결 강화/약화/유지에 대응한다. 기존 누적값을 읽는 방식으로 대신하지 않는다.
임의의 외부 판정 로직을 만들거나 가져오지 않는다.

```text
블록의 경험을 섞음
    → 셔플된 경험의 값을 SWEGCA 코어가 검증
    → 승인: 해당 연결 강화
      반려: 해당 연결 약화
      기권: 해당 연결 강도 유지
```

판정의 주체는 SWEGCA다. VRS가 먼저 강화·약화를 정해서 코어에 넘기지 않는다.
판정 대상 경험과 실제 갱신할 연결은 동일하게 결합돼야 한다.

## 현재 근거와 누락된 연결

1. 보존된 C++ 코어의 `EvidenceTally`는 축별 지지·반박값, 출처·맥락 다양성,
   최근 결과, 개정을 입력받는다. `verify_experience`와 `verify_connection`은
   이 입력을 호출자가 만든다는 계약이다.
2. 사용자 원본 `SWEGCA-Architecture@5901a5a`의 `EvidenceObservation`은 이미
   지정된 `axis`와 `outcome`을 받는다. 원본 집계는 같은 출처·맥락의 지지/반박
   비율을 계산하며, 셔플된 VRS 상태값에서 `axis/outcome`을 생성하지 않는다.
3. 원본 `tools/organize_rozephine_mixed_experience_connections_hybrid.py`의
   `refine_vrs`는 셔플된 연결을 따라 상태값을 갱신하고 별도 안정성을 계산한다.
   확인한 함수에는 SWEGCA 증거 집계로 연결하는 호출이 없다.

현재 **관측값이 기록된 경험의 셔플→코어 검증→해당 연결 강도 갱신**을 구현했다.
[실행 경로와 확인 범위](SHUFFLED_CONNECTION_PATH.md)에 근거를 기록했다.
집계형 인터페이스의 존재만으로 일반 세션 내용까지 처리되는 것으로 볼 수 없다.
보존 코어의 판정식과 사용자 원리를 유지하면서 남은 입력 연결을 구현해야 한다.
없는 검증 결과를 만들어 넣거나 별도 임계값 판정기를 추가하는 방식은 허용되지 않는다.

## 그동안 완료한 독립 작업

- `b41dfac`: 코어 판정과 VRS 변화 방향의 일관성, 원본 강도 연산 연결.
- `4a4a23d`: 원경험 본문·출처의 블록 저장, 주소 선택 읽기, 불완전 기록 보존.
- `0f41457`: VRS 공유 메모리 예산과 읽기 버퍼의 합산 계수.

위 작업들은 구성요소의 구현이다. 실제 셔플 검증, 판정 대상과 연결의 결합,
회상·재검증 경로의 완성을 증명하지 않는다. 구조 명칭이나 외곽 코드만 늘려
이 경로의 완성을 대신하지 않는다.

구성요소 구현·검사 통과를 전체 VRS 완료로 간주하지 않는다.
