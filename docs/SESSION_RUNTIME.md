# 세션 경험 처리와 임시/메인 조회 연결

2026-09-26. `SessionRuntime`이 저장·셔플·SWEGCA 검증·강도 갱신·세션별 최신 주소 발행을
한 호출로 연결한다. `ExperienceRouter`가 임시 우선 조회와 선택한 원경험의 읽기를 연결한다.

## 실행 경로

`define_connection`은 Main이 지정한 연결 ID·초기 강도·규칙을 받는다.
아직 관측이 없는 연결은 조회 후보로 발행하지 않는다.

`observe`는 다음을 순서대로 수행한다.

1. 원내용·출처와 관측값을 같은 원경험 기록에 저장한다.
2. 그 주소의 실제 관측값을 해당 연결에 추가한다.
3. 경험을 셔플하고 새 검증 입력을 구성해 SWEGCA 코어로 판정한다.
4. 승인/거절/기권에 따른 강화/약화/유지를 같은 연결에 기록한다.
5. 예상한 이전 주소와 계보를 검사해 세션별 최신 연결 목록에 발행한다.

기록 과정 실패 후에는 런타임을 다시 열어야 한다. 미발행 경험도 디스크에서 삭제하지 않는다.
사용 가능하지 않은 임시 상태를 검색 실패로 처리해 메인으로 넘어가지 않는다.

`record`는 관측값 없는 원내용을 그대로 보존한다. 이 함수만 호출했다고 일반 대화의 경험 처리나
검증이 완료된 것은 아니다. 임의의 자연어에 지지·반박 관측값을 만들어 붙이지 않는다.

## 조회와 읽기

- 런타임 시작 시 세션별 최신 연결을 원경험·코어 판정으로 복구한다.
- `recall`은 이미 메모리에 있는 연결 ID 색인을 조회한다. 이 호출에서 파일을 읽거나 복구·셔플하지 않는다.
- 임시 연결이 있으면 그 결과만 반환한다. 없을 때만 메인 색인을 조회한다.
- 메인에 등록할 수 있는 세션은 명시적으로 종료하고 원경험을 발행한 세션이다.
- 여러 메인 세션의 같은 연결 ID는 서로 다른 계보의 후보로 보존한다. 새 후보로 이전 것을 덮어쓰지 않는다.
- Main이 후보와 원경험 인덱스를 선택하면 `replay`는 그 연결에 속한 정확한 원경험 한 건만 읽는다.
- 원내용은 `evidence_payload`로 손실 없이 꺼낸다. NUL을 포함한 바이트도 보존한다.
- Recall 당시의 연결 헤드를 보존한다. Replay 전에 연결이 갱신되면 SWEGCA의 현재 헤드
  일치 검사로 오래된 결과의 사용을 거부하고 다시 Recall하도록 한다.

SWEGCA의 `recall_route_kernel.hpp`가 사용자가 지정한 임시 우선·메인 대체 순서와
종료·발행된 세션의 메인 조회 조건을 표현한다. 관측값의 의미 판정은 기존 증거 검증 코어가 수행한다.

## 확인

- 통합 검사 68회, 같은 검사의 UBSan trap 실행 통과.
- 지지 관측으로 강화, 반박 관측으로 약화, 불충분 관측으로 기권·유지를 확인했다.
- 관측 없는 정의의 미발행, 임시 우선, 임시 부재 시 메인 조회, 중복 메인 등록,
  여러 세션 계보 보존, 정확한 원내용 읽기, 잘못된 선택 인덱스 거부를 확인했다.
- 활성·종료만 된 세션의 메인 등록 거부, 명시적 종료·발행 후 등록을 확인했다.
- 실패한 임시 런타임이 메인 대체 조회로 숨겨지지 않는 것을 확인했다.
- 종료 세션 및 활성 세션을 다시 열어 같은 연결 강도·주소를 복구하고 후속 관측을 처리했다.
- 모든 런타임을 파괴한 뒤 공유 메모리 예산의 사용량이 0으로 돌아왔다.
- 전체 `make -j1 check` 통과. CPU 6·7만 사용하고 Palworld를 유지했다.

## 남은 범위

이 API의 조회 키는 연결 ID다. 자연 입력을 받는 Déjà vu 훅·region/portal 탐색,
현재 명제와 Replay의 대조 및 Re-evidence, 세션 간 그래프·강도 통합 병합은 아직 미구현이다.
원경험 발행과 메인 후보 등록을 그래프 병합 완료로 해석하지 않는다.

접근은 Main에서 직렬화한다. 결과와 내부 포인터는 런타임·라우터 변경 전에 사용하며,
세션 저장소와 메모리 예산은 런타임보다 오래 살아 있어야 한다. 재시작 복구는 콜드 경로이며
카탈로그 검증과 런타임 복원에서 판정을 다시 실행한다. 대규모 재시작 최적화는 남아 있다.
전체 입력→Recall 1ms 및 전체 프로세스 자원 제한은 아직 검증하지 않았다.
