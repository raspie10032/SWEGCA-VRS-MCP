# 종료 원천의 병합 준비와 Main 발행

MainGraph와 PersistentMainGraph의 `prepare_merge`는 종료·발행된 SessionRuntime의
실제 경험을 기존 Main 경험과 함께 셔플하고 SWEGCA 코어로 검증한다. 기존 `merge` 안의
준비 계산을 그대로 꺼낸 것이다. 새 판정 규칙, 이전 누적 판정 재사용, 외부 분류기를
추가하지 않았다. 준비 결과의 강도는 기존 승인/반려/기권 규칙을 따른다.

준비 결과는 불투명한 `MainGraph::PreparedMerge`다. 호출자가 판정·원경험·강도를
덮어쓸 수 없다. 준비 중에는 공개된 Main 연결, 세대, 영속 head가 변하지 않으며 저널을
쓰지 않는다. 기존 불변 경험 구간 공유와 연결별 병렬 계산을 유지한다.

## 동시 실행 계약

1. Main 소유자가 종료·발행된 원천의 수명을 확보한다.
2. 준비를 실행하는 동안 기존 Main의 읽기와 다른 활성 임시 세션의 기록은 가능하다.
   Main 쓰기, 원천 캐시 해제, 원천 저장소 해제는 금지한다.
3. 준비 워커를 모두 join한 뒤 Main 소유자가 `commit_merge`를 직렬 실행한다.
4. PersistentMainGraph는 기존 저널 쓰기·동기화를 마친 후 준비된 노드를 Main에 반영한다.
   저널 쓰기 실패 시 기존과 같이 reopen 전 사용을 거부한다.
5. 기존 조회 인덱스는 Main 소유자가 갱신한다. 변경된 Main의 옛 Replay 검증 규칙도 유지한다.

준비와 읽기의 동시 실행에는 thread-safe MemoryBudget upstream이 필요하다. 준비 결과와
Main이 공유하는 원경험 저장소, MainGraph 및 할당자는 결과 객체보다 오래 살아야 한다.
이 API 자체가 임의의 호출자 간 쓰기 경쟁을 잠그는 것은 아니다.

각 결과는 원래 Main 소유자와 준비 시작 세대를 기억한다. 다른 Main에 발행, move 이전
핸들 재사용, 이미 소비한 결과 재발행, 그 사이 Main 세대가 바뀐 결과의 발행은 거부한다.
오래된 결과는 새 Main 상태에서 다시 준비해야 하며, 외부에서 수치를 보정하지 않는다.
버린 준비 결과는 Main을 바꾸지 않고 임시 할당을 반환한다. 이미 병합한 원천 또는 빈
원천은 기존 `merge`와 같이 변경 없이 false를 반환한다.

기존 `merge`도 같은 prepare/commit 구현을 사용한다. 따라서 복구 시 결과 해시 검사,
영속 저널 형식, 연결 강도와 원경험 순서는 동일하다.

## 검사 범위와 남은 작업

검사는 준비 워커를 할당 지점에서 실제 정지시킨 동안 Main Recall/선택 Replay를 수행하고,
다른 활성 세션에 경험을 기록한다. 준비 완료 뒤 직렬 구현과 연결 강도·개정·원경험·코어
판정 해시를 비교한다. move/중복/다른 소유자/오래된 세대, 준비 중 무기록, 결과 폐기 후
메모리 반환, 발행 중 쓰기 실패와 복구를 포함한다.

네이티브 검사 결과: parallel-main 1,445개(할당 실패 223지점), persistent-main 224개,
main-graph 3,843개(할당 실패 742지점), runtime 128개, 실제 stdio 프로세스 1,105개 통과.
빌드·검사는 CPU 6·7 범위에서 실행했다. 이 변경에서 코어 수식과 저장 형식은 바꾸지 않았다.

이는 비동기 병합을 위한 실제 계산·발행 경계다. Runtime 작업 펌프와 stdio 서버는 아직
동기식이며, 원천 캐시 수명 고정·작업 스케줄링·완료 발행·조회 인덱스 갱신을 그 소유자에
연결해야 한다. 준비 중 읽기가 가능하다는 검사로 실서비스 입력 지연이나 실제 클라이언트
연결 완료를 주장하지 않는다.
