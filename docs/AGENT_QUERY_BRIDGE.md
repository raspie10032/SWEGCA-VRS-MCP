# 에이전트 조회에서 소유 VRS까지

## 소유권과 실제 경로

데스크톱 호스트가 수명마다 0700 임시 디렉터리를 만들고 `SWEGCA_QUERY_SOCKET`을
자식에게 전달한다. 기존 VRS 프로세스가 이 경로에 0600 Unix 소켓을 연다.
관측 MCP 프로세스도 같은 경로를 전달받으며 `vrs_replay`를 추가로 제공한다.
별도 Main, 별도 경험 저장소, 외부 판정기, 모델 호출은 만들지 않는다.

1. 에이전트는 입력 문맥에 있는 receipt와 inputOriginal을 함께 제공한다.
2. MCP 어댑터는 `swegca/agent/replay`로 요청을 소유 VRS에 전달한다.
3. 소유 호스트는 살아 있는 native 입력/복구 영수증과 정확한 원경험 주소를 확인한다.
4. 해당 세션을 선택하여 기존 일반 또는 scoped Replay/대조/충돌 재검증을 수행한다.
5. 성공/실패 모두 이전 호스트 세션 선택을 복원한다. 반환한 관측/강도/원문은 기존
   VRS의 결과이며 어댑터가 새 verdict를 생성하지 않는다.

인자는 receipt/inputOriginal 및 선택적 scope 또는 related boolean이다.
related=true는 선택된 부모 원경험의 관측 연결을 따라가며 scope와 함께 지정할 수 없다. scope는 생산자가 기록한 정확한
범위 문자열이다. 에이전트가 세션 선택, 원경험 추가, 정책 변경, 종료, Main 병합,
임의 seed/step/candidate를 이 경로로 요청할 수 없다. 일반 host 관리 API를 소켓으로
노출하지 않는다. inputOriginal은 행동 권한이 아니며 재시작 전 영수증을 영속 주소처럼
사용할 수 없다. 파생 cognition 개정은 기존 소유 호스트 경로대로 저장될 수 있다.

## 전송과 자원

동일 uid의 로컬 프로세스만 받으며 TCP 포트는 열지 않는다. 활성 연결은 최대4개,
요청은 64KiB, 연결 수명은 30초다. 부분 읽기/쓰기와 대기는 비차단으로 처리한다.
주 입력 스트림에 완성 중인 프레임이 없고 읽을 입력도 없을 때 idle 경로에서만
조회 소켓을 진행한다. 주 스트림과 소켓이 동시에 Server를 실행하지 않는다.
SWEGCA 판정식이나 입력→Déjà vu→Recall 앞에 작업을 추가하지 않았다.

응답은 VRS PMR 예산과 host frame 한도 안에서 구성하며 MCP 클라이언트에는 별도
64MiB 응답 프레임 상한이 있다. 한도를 넘기면 실패하며 조용히 원문을 자르지 않는다.
조회 처리 도중 들어온 입력의 지연을 포함하는 최악 응답 시간은 이번 검사가 증명하지
않는다. 기존 1MiB 입력→Recall 1ms 실패는 여전히 해소되지 않았다.

VRS 종료 시 소유 inode가 같은 소켓만 정리한다. 데스크톱 호스트는 자식 종료 후
전용 소켓/디렉터리를 정리한다. 종료/EOF는 기존대로 경험의 명시적 종료·Main 병합
권한이 아니다.

## 검증과 설치

- CPU6-7 / make -j2, 실제 stdio subprocess 5903 checks 통과.
- 실제 C++ MCP 클라이언트→소켓→소유 VRS 왕복 원경험 일치, 다른 선택 세션의
  조회 뒤 원래 선택 복원, 주소/인자 불일치 거부, 종료 명령 차단, 부분 요청 중
  주 스트림 ping 처리, scoped 조회와 재시작 복구 경로를 확인했다.
- 실제 host/proxy/VRS와 합성 backend에서 전달된 문맥을 사용해 MCP 클라이언트가
  선택 원경험을 다시 조회했다. 선택 주소/입력 주소 일치와 소켓/디렉터리 정리를 확인했다.
- 파일 관측기129 / wrapper41 checks도 통과했다.
- 기존 설치본 해시와 비실행 상태를 확인하고 VRS/관측기/proxy/host를 갱신했다.
  resources.json/proxy.json/Main identity/원경험을 보존하고 manifest 해시를 확인했다.
- 실제 설치 backend의 목록에서 vrs_replay와 필수 receipt/inputOriginal 스키마를
  확인했다. VRS/관측기가 같은 소켓을 사용하고 소켓0600/디렉터리0700임을 확인했다.
  종료 뒤 정리, 동일 cgroup 3999997952B RAM / swap0 / CPU6-7 / 공유 I/O를 확인했다.
  모델 호출0, 새 task/대화 생성0, 정상 종료였다.

실제 GUI 에이전트가 이 도구를 선택해 목적 유지에 사용하는 검증은 아직 남았다.
자연어 요구 자동 추출, 관측의 의미 적합성, 전체 요구 충족 판정, 대규모 자원/지연
조건 및 장기 압축 평가는 완료되지 않았다.
