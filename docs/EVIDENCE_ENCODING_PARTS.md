# 원경험 기록 시 전체 인코딩 복제 제거

`record_evidence`는 기존에 `176 + media.size + content.size` 바이트의 임시 PMR 벡터를
만들고 원문 전체를 복제한 뒤 블록에 기록했다. 지금은 176바이트 관측 헤더만 스택에
구성하고, 기존 미디어 문자열과 원문 span을 블록 작성기의 내부 append_parts에 전달한다.
사용하지 않게 된 MemoryBudget 인자는 함수와 호출부에서 제거했다. 옛 호출용 overload는
남기지 않았다.

## 보존한 계약

- 원경험·관측의 입력 유효성, 출처, 시각 일치, 크기 overflow 검사를 유지한다.
- 모든 부분이 블록 용량에 들어가는지와 VRS 저장 예산을 쓰기 전에 검사한다.
- 기록 헤더의 총 길이, 관측 인코딩, 원문 바이트, SHA-256, 완료 trailer는 동일하다.
- 각 부분의 모든 바이트를 기존 TransferBudget을 거쳐 기록하고 fdatasync 후 주소를 반환한다.
- 쓰기 실패 시 writer를 사용 불가로 만들고 완료/미완료 바이트를 보존한다.
- PersistentConnection의 기록 후 읽기 검증, 복구 중 원문·체크섬 검증, SWEGCA admission,
  셔플, 승인/반려/기권 강도 갱신을 생략하지 않는다.

공개된 일반 ExperienceBlock::append는 동일한 내부 경로에 한 개의 content span을 전달한다.
부분 기록 함수는 private이며 원경험 관측 인코더만 추가로 사용할 수 있다. 구조적 그래프
분할이나 region/portal 구성 규칙을 이 물리 기록 변경으로 대체하지 않는다.

## 검증과 한계

2MiB 바이너리 payload를 사용해 분할 기록과 한 개 연속 payload 기록의 **전체 파일 바이트**,
원경험 주소, cue, 디코딩된 관측과 원문이 일치하는지 검사한다. 기존 15개 refinement digest
고정 벡터도 계속 검사하므로 기존 기록 주소를 포함한 판정 결과의 변화 여부를 확인한다.
블록 용량 부족은 쓰기 전에 거부하며 정상 writer 상태를 유지하는지 확인한다.

작은 비어 있지 않은 원문을 사용해 8개 쓰기 경계 각각에서 실패를 주입한다. 어느 경계에서
실패해도 이전 원경험이 그대로 읽히고, 실패한 writer가 추가 기록을 거부하는지 검사한다.

네이티브 검사 결과: connection 15,020개, experience-block 151개, Runtime 수명주기 128개
통과. 빌드는 CPU 6·7, 최대 2개 컴파일 작업으로 실행했다.

이 변경은 인코딩 단계의 payload 크기 임시 복제를 없앤 것이다. **Runtime 전체의 메모리
최댓값이 그만큼 감소한다고 주장하지 않는다.** 기존 읽기 검증과 선택 Replay는 여전히
원경험 전체 버퍼를 사용하며, 호출자의 원문 버퍼도 필요하다. 큰 원경험 복구·Replay의
스트리밍 검증은 별도로 남아 있다. 부분별 기록으로 작은 pwrite 호출 수가 늘 수 있으므로
이 변경만으로 쓰기 지연 개선을 주장하지 않는다.
