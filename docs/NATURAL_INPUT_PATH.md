# 자연 입력에서 원경험 주소까지

2026-09-26. `ExperienceRouter::input(media, bytes)`가 입력 원문을 받아 즉시
SWEGCA의 내용 주소 함수 `input_cue`로 Déjà vu의 일치 키를 만든다.
뒤이어 `recall_cue`가 실제 연결 및 원경험 위치를 활성화한다.
파일 쓰기·원경험 읽기·복구·셔플·LLM 호출은 이 두 단계 앞에 없다.

## 현재 구현

- 원문 전체와 미디어 형식을 길이 구분하여 SHA-256 내용 주소를 구성한다.
  같은 바이트가 같은 키가 되는 정확한 일치 탐색이다. 의미 유사도 판정이 아니다.
- 키는 체크섬이 확인된 원경험의 내용에서 만들며 원경험 바이트·미디어 형식을 변경하지 않는다.
- 세션에서 경험을 처리할 때 키 → 연결 ID·원경험 인덱스를 메모리에 반영한다.
  영속 목록 발행 이후 필요한 벡터 공간은 미리 확보한다.
- 재시작 시 이미 수행하는 원경험 검증·연결 복원에서 키를 함께 재구성한다.
  입력 시점에는 원문을 다시 읽거나 과거 로그를 검색하지 않는다.
- 임시에서 일치 경험이 있으면 그 경험들을 활성화한다. 부재일 때만 발행된 메인 경험을 조회한다.
- 동일한 원문에 연결된 성공·반박·불확실 경험을 모두 후보 주소로 보존한다.
- 원문이 일치하지 않으면 직전에 성공적으로 Replay한 연결의 경험을 이어지는 대화의 후보로 찾는다.
  임시의 원문 일치·연속 문맥을 먼저 검사하고, 둘 다 없을 때만 메인을 검사한다.
  한 계층 안에서는 원문 일치를 먼저 선택한다. 이 순서는 SWEGCA `familiarity_key`와
  `recall_scope`로 결정한다.
- 결과에 원문 일치인지 연속 문맥인지 기록한다. 연속 문맥은 현재 명제와의 일치 판정이 아니다.
- 연결 키는 원경험을 성공적으로 읽은 뒤에만 바뀐다. 읽기 실패·오래된 헤드·잘못된 선택으로는
  다음 대화의 기억 키를 바꾸지 않는다. 새 라우터는 이전 라우터의 대화 키를 자동 상속하지 않는다.
- `InputRecall`은 각 후보의 연결 헤드와 원경험 인덱스를 소유한다.
  다른 입력으로 후보 벡터가 늘어나도 기존 결과의 주소 배열을 빌려 쓰지 않는다.
- Replay는 선택한 후보의 당시 연결 헤드를 확인한 뒤 그 원경험 하나를 읽는다.

`retain_input`은 별도 결과 관측이 없는 자연 입력도 관측 경험 저장·셔플·SWEGCA 검증·연결 발행
경로에 넣는다. 입력의 출처 이름과 세션 이름을 각각 출처·문맥 식별자로 묶고, 결과는
`insufficient`로 보존한다. 승인이나 반박을 텍스트에서 임의 생성하지 않는다.
초기 강도와 SWEGCA 규칙은 Main 소유 호출자가 지정한다.

## 빈 증거 상태 수정

이 경로를 검사하면서 보존 코어의 `revision == 0` 일괄 거부가 사용자 원본과 다름을 확인했다.
원본 `mosaic_evidence_accumulator.py`의 `EvidenceAccumulatorState.empty()`는 개정 0의 정규 상태를
발행하며 `assess_accumulator()`는 이를 `minimum_effective_samples`에 따른 기권으로 판정한다.

빈 증거는 같은 원본 판정식으로 평가하도록 수정했다. 개정 0인데 표본·다양성·최근 관측을
주장하는 모순된 입력은 계속 거부한다. 검증되지 않은 기본 판정 객체의 무효 상태도 유지한다.
이로써 불충분한 경험만 들어온 경우에도 정상적인 기권·강도 유지가 된다.

원본 대조 검사는 기존 판정 상태 외에 이유도 비교하도록 보강했다. 빈 배치 및 불충분한
경험만 있는 배치를 포함한다. 승인/거절 경계식과 관측값 집계 규칙은 변경하지 않았다.

## 확인

대화 연속 키 추가 후 런타임 검사 **101회와 UBSan trap 검사**를 통과했다.
원문 부재 시 이전 Replay 연결 조회, 새 라우터의 문맥 비상속, 원문 일치와 연속 문맥의 구분,
임시 문맥의 메인보다 우선 조회, 원경험 읽기 실패 후 기존 대화 키 유지, 조회 중 I/O 부재를 확인했다.
키 선택 코어 함수는 0.95441ns, 4축 판정은 44.3996ns였다. 같은 예열·묶음 측정 조건이며
출력은 `measurements/continuity-core-20260926.txt`에 보존했다.

앞선 원문 입력 경로 및 빈 증거 처리 수정의 전체 검사:

- 전체 검사 통과: 코어 3,961, VRS 38, 블록 88, 메모리 31 및 경합 2,000회,
  연결 1,437 및 할당 실패 지점 246개, 세션 169, 영속 연결 65, 카탈로그 60,
  세션 런타임 87, 컴파일 계약 15개.
- 세션 런타임 87회는 UBSan trap 구성에서도 통과했다.
- 원본 Python과 셔플 배치 14개·관측값 1,008개의 집계·판정·판정 이유 일치.
- 런타임 검사에서 `pread`/`pwrite` 호출을 계수했다. 입력→주소 Recall 동안 두 호출이
  늘지 않으며, 선택한 원경험 Replay부터 읽기가 발생한다.
- UTF-8 자연 입력, NUL 포함 원문, 미디어 형식 구분, 임시 우선, 메인 부재/존재,
  결과가 불충분한 입력의 기권·강도 유지, 세션 재시작 후 동일 키 복원을 확인했다.
- 코어 4축 판정 44.051ns, 판정+강도 갱신 51.0242ns. CPU 7, GCC 16.2.1, `-O3`.
  100,000회 예열 후 100,000회씩 31묶음의 평균 중앙값이며 전체 경로 지연이 아니다.
  원문 출력은 `measurements/empty-evidence-core-20260926.txt`에 보존했다.

## 범위

현재는 원문 전체의 일치 키와 성공적으로 Replay한 기억의 연결 키를 사용한다.
연속 문맥의 키는 Main 런타임 안에 유지하며, 프로세스 재시작 후 대화 위치 복구는 남아 있다.
region·portal·공유 경험 탐색, 현재 명제와 Replay의 의미 대조·Re-evidence 및 실제 클라이언트 입력 훅은 남아 있다.
원문 일치를 곧바로 현재 사실에 대한 승인이나 행동 권한으로 사용하지 않는다.

내용 주소 계산 시간은 Déjà vu 비용이다. 이후 입력→Recall 측정에 SHA-256을 반드시 포함한다.
이 문서는 전체 입력 경로의 1ms 달성을 주장하지 않는다. 큰 입력·큰 색인의 규모별 시간과
전체 4GB RSS 조건은 아직 검증하지 않았다.
