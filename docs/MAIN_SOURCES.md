# Main 원천 자동 발견과 저장소 소유

2026-09-26. `MainSources`는 `MainSourceResolver`의 디스크 구현이다.
원천 세션 ID를 테스트용 객체 목록으로 주입하지 않아도 영속 Main 병합 이력을 복구한다.

## 발견·검증·소유

- `main/<64자리 소문자 hex>.session` 발행 파일만 발견한다. 활성 세션이나 종료만 된
  세션을 자동 종료·발행하지 않는다. 관련 이름의 잘못된 파일·심볼릭 링크는 거부한다.
- SessionStore의 기존 검증으로 세션 ID, 종료 inventory, 원경험 블록, 발행 파일과
  종료 마커의 동일성을 확인하고 SWEGCA 세션 조건으로 종료·발행 상태를 요구한다.
- MainSources가 SessionStore 소유권을 유지한다. 기존 쓰기 소유자가 살아 있으면 잠금
  충돌로 거부한다. Runtime은 처음부터 MainSources가 소유한 저장소를 빌려 쓰고,
  종료·발행 후 활성 사용권을 반환한다. 외부에서 따로 연 저장소의 중복 소유는 여전히 거부한다.
- 복구·병합은 한 번에 한 비활성 원천의 SessionRuntime 캐시를 보유한다. 활성 세션이
  빌려 쓰는 캐시는 별도로 보호한다. 다음 원천을 처리하면 이전 비활성 캐시를 해제한다.
  `release_caches()`도 활성 사용권이 있는 캐시는 해제하지 않는다.
- 해제 후에도 원경험 저장소는 유지하므로 통합 Main의 선택 Replay는 유효하다.
  MainSources는 자신을 사용하는 Main 그래프·라우터보다 오래 살아 있어야 한다.
- 자료구조·소유 객체·해석 캐시 할당은 호출자가 지정한 VRS MemoryBudget을 사용한다.

## 미병합 처리

`merge_published(graph, seed, step)`은 Main 소유자의 작업 처리 호출이다.
발견한 ID를 정렬해 이미 병합된 원천을 건너뛰고 각 원천을 기존 영속 병합 경로로 처리한다.
실제 셔플·SWEGCA 판정과 기록 조건은 그대로 사용한다. seed와 step은 Main이 제공한다.
완료되거나 실패하면 해석 캐시를 해제한다.

각 세션은 독립된 영속 커밋이다. 나중 세션에서 실패해도 앞서 완료한 병합은 유지되고,
다시 호출하면 완료된 원천을 중복 강화하지 않는다. 연결이 전혀 없는 종료 세션은 기존
MainGraph 규칙대로 병합 루트를 만들지 않으며 다음 처리 호출에서도 다시 검사할 수 있다.

이 호출은 입력·Recall 안에서 실행하지 않는다. 실제 호스트의 종료 이벤트·작업 스케줄러와
라우터 인덱스 갱신은 다음 통합 대상이다. 임의 idle 타이머를 세션 종료로 간주하지 않는다.

## 확인 범위

검사 32개가 일반 실행 및 UBSan trap 실행에서 통과했다. CPU 6·7만 사용했다.

활성·미발행 세션 제외, 실제 종료·발행 이후 새 경험 병합, 재시작의 디스크 원천 복구,
캐시 해제 이후 원경험 Replay, 중복 처리에서 원경험 파일 재읽기 없음, 잘못된 발행 이름·링크
및 누락 원천 거부를 검사한다. 원본 소유자를 두 번 열 수 없고 모든 객체 해제 뒤 공유
예산 사용량이 0으로 돌아오는 것도 확인한다.

체크포인트·분할 복구, 백그라운드 병렬 작업, 실제 호스트 배포 및 전체 RSS·I/O·지연 검증은
아직 남아 있다. 디렉터리 발견과 저장소 복구는 콜드 경로다.
