# 종료된 세션 경험의 Main 연결 병합

2026-09-26. `MainGraph`는 **메모리 안의 병합 소유자**다.
`PersistentMainGraph`가 병합 기록의 영속 발행·재검증 복구를 연결한다.
입력 라우터의 통합 그래프 조회는 `mount_main(PersistentMainGraph)`로 연결했다.

## 처리

- Main이 초기 강도와 SWEGCA 규칙을 명시해 그래프를 만든다.
- SWEGCA 세션 조건으로 명시적으로 종료·발행된 세션만 병합한다. 활성 세션이나 종료만 된
  세션은 거부한다. 원경험 발행 이후에만 병합한다.
- 같은 연결 ID의 기존 메인 경험과 새 세션 경험을 합친다. 원문은 복사하지 않으며,
  관측값·출처·주소를 보존한다.
- 합친 실제 경험을 새로 셔플하고 SWEGCA 코어로 검증한다. 기존 메인 강도에 승인→강화,
  거절→약화, 기권→유지를 적용한다. 새 연결은 Main이 지정한 초기 강도에서 시작한다.
- 세션별 최종 강도를 합산하거나 평균 내지 않는다. 세션 내부의 반복 정련 횟수가 그대로
  메인 강화 횟수가 되지 않는다.
- 병합 이력은 세션 ID와 발행 루트에 묶는다. 같은 세션을 재요청해도 다시 강화하지 않는다.
- 한 세션이 여러 연결을 갱신할 때, 모두 준비된 뒤 Main의 직렬 소유 구간에서 한꺼번에 반영한다.
  준비 실패 시 기존 연결·강도·세대·병합된 세션 목록을 그대로 둔다.
- 새 결과의 강도 투영이 무효이거나 원본 세션 규칙이 Main 규칙과 다르면 일괄 병합을 거부한다.
  규칙을 임의 변환하거나 경험을 삭제하지 않는다.

## 원경험 읽기와 자원

연결의 각 경험은 원래 `SessionStore`와 정확한 원경험 주소를 가리킨다.
선택한 경험 하나를 원래 저장소에서 읽고 그 주소를 대조한다. 병합 후 원래 세션의
`SessionRuntime` 캐시는 해제할 수 있다. 저장소 객체는 그래프 조회 동안 살아 있어야 한다.

변경 대상 연결의 관측 메타데이터를 준비 사본으로 구성한다. 전체 메인 그래프나 원문을
매번 복사하지 않는다. 할당은 Main의 공유 VRS 예산을 통과한다. 연결 자체가 매우 커질 때의
분할·체크포인트는 아직 남아 있으며, 이 준비 사본만으로 4GB 전체 RSS 준수를 주장하지 않는다.

## 다음 통합

병합 원천·순서·셔플 조건·결과의 영속 기록과 복구는
[영속 Main 문서](PERSISTENT_MAIN_GRAPH.md)에 기록했다. 직접 사용하는 `MainGraph`는
여전히 메모리 객체이며, 영속성이 필요한 소유자는 `PersistentMainGraph`를 사용한다.
입력 라우터 연결은 [Main 조회 문서](MERGED_MAIN_QUERY.md)에 기록했다.
원천 자동 발견 및 종료 후 작업 스케줄링의 통합은 남아 있다.

## 확인

- 병합 검사 3,695회 및 같은 검사의 UBSan trap 실행 통과.
- 활성 세션·미발행 종료 세션 거부, 종료·발행 이후 허용, 중복 병합의 무변경을 확인했다.
- 별도로 합친 실제 원경험을 기존 `Connection::refine`으로 검증한 결과와 Main 강도·판정이 일치했다.
- 새로운 반박 경험을 합치면 해당 연결이 약화됐고 원래 세션들의 연결 헤드는 바뀌지 않았다.
- 여러 연결의 일괄 준비에서 할당 실패 지점 732곳을 주입했다. 모두 기존 세대·강도·경험 개수와
  병합 이력을 보존했고 공유 할당 사용량도 기존 값으로 돌아왔다.
- 두 번째 연결의 규칙 불일치로 실패할 때, 먼저 준비한 첫 연결도 반영되지 않았다.
- 병합 중 파일 읽기·쓰기가 없음을 계수했고, 선택 원경험의 정확한 주소 읽기를 확인했다.
- 원래 세션의 런타임 캐시를 해제한 뒤에도 원래 저장소에서 Replay할 수 있었다.
  같은 저장소의 캐시를 다시 복원해 병합을 재요청해도 다시 강화하지 않았다.
- 검사·빌드는 CPU 6·7에 제한했고 Palworld 실행을 유지했다.
