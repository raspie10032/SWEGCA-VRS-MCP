# 실제 바이트 관측 생산

`observe_file_equality`는 호출자가 이미 연 두 일반 파일을 실제로 읽는다.
확인 대상 술어는 **두 파일의 바이트 내용이 같다**다. 파일 이동 완료,
권한 보존, 사용자 목적 전체 충족을 뜻하지 않는다.

원본 `ARCHITECTURE_SPEC.md` §4.3–4.4의 생산자 관측과 권위 있는 증거 판정을
구분한다. `observe_content_equality` 코어 함수가 완전성·안정성·일치 관측을
support/refute/insufficient로 옮긴다. 이는 관측값이며 SWEGCA의
accept/reject/abstain 판정이나 연결 강도 갱신을 직접 수행하지 않는다.
기존 `judge_evidence` 판정식과 셔플·강도 갱신 코드는 수정하지 않았다.

## 자원 및 출처

- 파일을 열거나 명령을 실행하지 않는다. 이미 허가받아 연 descriptor를 빌리며,
  descriptor 소유권과 현재 seek 위치는 호출자에게 유지한다.
- 양쪽을 32KiB씩 읽는다. 총 64KiB scratch는 호출자의 PMR 자원에 계수한다.
- 읽기 요청과 EOF 확인, EINTR 뒤 재요청도 공용 `TransferBudget`에 계수한다.
- 파일별 최대 바이트 수를 받는다. 전체 파일보다 한도가 작으면
  일부만 비교해서 지지/반박하지 않고 insufficient로 남긴다.
- 실제 읽은 바이트의 SHA-256, 길이, 읽기 전후 device/inode/크기/시각 등
  stat 자료를 결과에 남긴다. 바이트 일치는 직접 비교하며 해시로 대신하지 않는다.
- 첫 불일치 뒤에도 읽기를 마친다. 이후 읽기 실패가 있으면 불완전 관측이다.
- st_size만 믿지 않고 EOF를 확인한다. 크기가 0으로 보고되는 procfs 내용을
  빈 파일과 같다고 잘못 관측하지 않는다.
- 크기·mtime·ctime 등에서 관측된 변경이 있으면 insufficient다. 이 검사는
  두 파일의 원자적 스냅샷이나 적대적 동시 변경에 대한 보증이 아니다.
  그런 보증이 필요한 호출자는 불변 스냅샷을 제공해야 한다.

## 아직 연결하지 않은 부분

후속 구현에서 C++ MCP 관측 생산자에 연결했다(CONTENT_OBSERVER_MCP.md).
실제 측정 응답의 native 저장/재시작 복구를 검증했다. 설치된 데스크톱 등록,
자동 파일 탐색, 명령 실행은 수행하지 않았다.

자동 연결 전에 원래 입력과 **어떤 요구사항을 검증하는 관측인가**를 결합해야 한다.
네이티브 보고의 명시적 scope를 별도 연결로 보존하는 단계는 SCOPED_OBSERVATIONS.md에
추가했다. scope가 없는 보고는 여전히 입력 전체를 대상으로 한다. 이 파일 관측 함수를
그 경로에 무조건 주입하거나 일반 자연어 검증기의 완료로 보고해서는 안 된다.

명시된 범위의 보존은 연결됐지만 자연어에서 검증 대상/근거의 범위를 추출하는 부분은 남았다. 자연어에서
그 범위를 확인하지 못하면 미확인 상태를 유지해야 한다. 키워드나 파일 경로 존재로
의미를 추정하거나 임의로 전체 목적의 성공으로 확대하지 않는다.

## 검증

CPU 6,7에서 `make -j2 build/file-observation-tests` 후 실행: **52 checks passed**.
실제 임시 파일의 빈 내용/바이너리/32KiB 경계/길이 및 내용 불일치, 파일 위치 보존,
EINTR·짧은 읽기, 불일치 이후 I/O 오류, 같은 크기의 중간 변경, 크기 제한,
PMR 할당 실패, pipe/잘못된 descriptor/procfs, 자원 반환을 검증했다.
실패 주입은 테스트 바이너리의 `--wrap=pread`에만 존재한다.

이 결과는 일반 자연어 의미 해석, 실제 데스크톱 통합, 1ms 입력 지연,
대규모 4GB 운용 또는 전체 VRS 완성의 증거가 아니다.
