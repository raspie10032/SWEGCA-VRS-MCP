# 백그라운드 복구·병합 중 입력→Recall 측정

현재 C++ Runtime의 실제 입력 경로를 측정했다. 실제 Codex 입력 훅, MCP 전송 지연,
Replay 완료 시간 또는 모델 성능평가를 측정한 결과가 아니다.

## 구성

- CPU 6·7, 컴파일 종료 후 실행. 서비스·Palworld 설정 변경 없음.
- VRS MemoryBudget 64MiB, 종료된 원천에 실제 경험 2,048개를 기록하고 재개방.
- Main에는 0/128/4,096/65,536/1,048,576바이트 원문을 미리 발행.
- 활성 임시 세션에도 동일 크기의 다른 미디어 키 경험을 기록.
- 종료 원천의 복구 및 셔플·코어 검증을 schedule_work로 실행하면서 Main·임시·부재
  각 경로를 조회. 각 입력 크기/경로당 5회 준비 실행 후 30회, 총 450개 표본.
- merge_workers=2지만 대기 원천의 연결은 하나다. 2개 독립 연결을 병렬로 계산하는
  부하나 전체 16스레드 부하를 의미하지 않는다.

계측 시작은 `Runtime::input` 호출 직전, 종료는 기존 Recall 진입 probe다. worker probe는
실제 원천 복구·병합 준비의 시작/끝을 표시한다. 표본 전후 모두 워커 구간 안인 표본만
overlappedSamples에 포함한다. 작업이 끝난 뒤 측정한 표본은 별도 수치로 분리한다.
두 probe는 전용 컴파일 매크로에서만 존재하며 일반 빌드에는 호출이 없다.

입력 스레드의 pread/pwrite는 thread_local 계수로 검사해 배경 워커의 정상 I/O와 구분한다.
Main·임시·부재 라우팅, owner poll 이전 미발행, 최종 선택 원경험의 동일 주소, 전체
Runtime 해제 후 추적 할당 0도 검사한다. 페이지 캐시를 비우지 않았으므로 물리 SSD의
콜드 읽기 시험은 아니다.

## 최초 결과 — 지연 요구 미달 사례

`benchmarks/results/background-recall-2048.jsonl`의 450개 표본은 모두 실제 작업 구간과
겹쳤다. 다음 두 표본이 1ms 이상이었다.

| 경로 | 입력 크기 | 입력→Recall 최대 |
| --- | ---: | ---: |
| 부재 | 65,536바이트 | 3,507,246ns |
| 부재 | 1,048,576바이트 | 1,071,401ns |

Main/임시 1MiB 입력 중앙값은 각각 455,395ns/455,385ns였다. 준비 예약부터 발행 완료는
228.452ms, 마지막 poll 발행 구간은 371,553ns였다. 이는 다른 크기·부하에서 발행 구간의
상한을 보장하는 값이 아니다. 종료 원천 작업을 입력 밖으로 옮겼다는 이유로 모든 입력이
1ms 미만이라고 결론 내릴 수 없다.

## 원인 계측과 한계

후속 계측은 입력 스레드 CPU 시간과 자발적/비자발적 문맥 전환을 추가했다. 초과 표본이
있으면 그 표본의 입력→Recall wall time, input 반환까지의 thread CPU time, 문맥 전환
차이를 함께 기록한다. CPU time의 종료점은 Recall 진입보다 뒤이므로 같은 측정값으로
해석하지 않는다.

`background-recall-2048-thread-timing.jsonl` 및 `background-recall-thread-diagnostic-1..5.jsonl`
6회에서는 각 450개, 총 2,700개의 겹친 표본에서 1ms 초과가 재현되지 않았다. 추가 계측이
스케줄링 시점에 영향을 줄 수 있으므로 이 재실행을 수정 효과나 최초 실패의 무효화로
해석하지 않는다. 최초 실행에는 thread CPU/전환 정보가 없어 원인을 확정할 수 없다.
추측으로 OS 스케줄러 책임을 단정하거나 최초 실패 표본을 제외하지 않았다.

결론: 실제 배경 작업과 입력의 동시 실행 및 원경험 보존은 이 제한된 구성에서 확인했다.
입력→Recall 1ms 상한은 미달 사례가 남아 **미완료**다. 실제 앱 연결과 자원 배치가
정해진 뒤 동일 경계에서 원인 계측 및 개선을 이어가야 한다. 일반 SSD/RAM 프로파일 전체,
500GB 경험 규모, 임의 입력 크기의 지연 요구를 증명한 결과가 아니다.

재실행:

```sh
taskset -c 6,7 make -j1 build/background-recall-bench
# 빌드가 끝난 후
taskset -c 6,7 build/background-recall-bench
```
