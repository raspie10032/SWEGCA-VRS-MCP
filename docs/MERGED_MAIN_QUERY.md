# 통합 Main 그래프의 입력 조회

2026-09-26. `ExperienceRouter::mount_main(PersistentMainGraph)`가 영속 Main 그래프를
자연 입력 및 연결 ID 조회 경로에 연결한다. 같은 연결의 병합된 경험 주소와 SWEGCA로
갱신한 Main 강도를 반환한다.

## 경로와 수명

- 자연 입력에서 기존 SWEGCA 입력 키를 바로 만들고 임시 경험부터 찾는다.
  임시에 없을 때만 Main의 미리 구성된 키 인덱스를 조회한다.
- 정확한 입력 키와 성공한 Replay의 대화 연결 키를 사용한다. 이것이 일반 문장의
  의미를 검증하거나 진실성을 판정한다는 뜻은 아니다.
- Recall은 주소·강도·개정을 반환한다. 원문 파일 읽기나 병합은 하지 않는다.
- Replay는 선택한 원경험 하나를 기존 저장소에서 읽는다. 원천 SessionRuntime 캐시는
  조회에 필요하지 않으며, Main 그래프와 원경험 SessionStore 소유자는 살아 있어야 한다.
- 병합 후 기존 조회 인덱스는 Main 부재로 취급하지 않고 갱신 필요 오류를 낸다.
  임시에서 이미 찾은 경험은 계속 조회할 수 있다.
- `mount_main` 재호출은 새 인덱스를 모두 준비한 뒤 교체한다. 준비 중 실패하면
  기존 인덱스가 유지된다. 병합·갱신·읽기는 Main이 직렬 소유한다.
- 보유한 자연 입력 Recall은 Main 헤드와 코어의 동일 개정 검사를 통과해야 Replay한다.
  병합 후에는 인덱스를 갱신했더라도 오래된 Recall로 읽을 수 없다.
- 성공한 Replay의 재검증은 그 원경험과 조회 이후의 임시 관측을 사용한다.
  Main 연결 노드가 교체돼도 폐기된 노드 포인터를 읽지 않는다.
- 직접 연결 ID 조회의 `RecallCandidates`는 기존과 같이 빌린 뷰다. 라우터 변경 전에
  사용해야 한다. 자연 입력의 `InputRecall`은 후보 복사본을 소유한다.

세션별 Main 후보의 개별 발행 경로도 존재하지만, 한 라우터에서 통합 Main과 혼용하지
못하게 한다. 같은 원경험을 두 계층으로 중복 후보화하지 않는다. 실제 서비스 통합에서는
영속 Main 소유자를 사용한다.

## 검증

- 영속 Main/통합 조회 검사 70개: 일반 실행과 UBSan trap 실행 통과.
- 임시 우선, Main 통합 강도, 같은 연결의 여러 원천 주소, 대화 연결 키,
  병합 전 Recall의 거부, 병합 이후 과거 Replay의 현재 관측 재검증을 확인했다.
- 재시작 복구 후에도 동일한 통합 경험·강도와 원경험 주소가 조회됐다.
- 조회 직전·직후 `pread` 횟수가 같았다. Replay는 선택 주소와 정확히 일치했다.
- 인덱스 갱신의 할당 실패 7곳 모두 기존 인덱스·할당량을 보존했다.
- 기존 세션 런타임 회귀 검사 234개 통과.

## 남은 범위

원천 자동 발견과 미병합 처리 호출은 [Main 원천 문서](MAIN_SOURCES.md)에 기록했다.
호스트 훅, 종료 후 병합 및 조회 인덱스 갱신 스케줄링은 남아 있다.
현재 인덱스 갱신은 전체 주소 인덱스를 준비한다. 대규모 분할·증분 갱신·동시 스냅샷은
추가 구현 대상이다. 실제 입력→Recall 1ms, 전체 4GB RSS 및 I/O 조건은 아직 입증하지 않았다.
