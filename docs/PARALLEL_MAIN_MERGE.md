# SWEGCA 연결별 Main 병합 병렬 처리

2026-09-26. MainGraph의 변경 대상 연결들을 여러 작업 슬롯에서 준비하도록 연결했다.
한 연결 내부의 셔플·출처/맥락 집계·SWEGCA 판정·강도 연산 순서는 그대로 유지한다.

## 처리 경계

1. Main이 원천의 종료·발행 상태와 모든 연결의 규칙 일치를 검사한다.
2. 연결별 준비 객체와 작업 목록을 공유 VRS 예산으로 만든다.
3. 연결별 독립 작업을 여러 슬롯에 나눠 처리한다. 각 슬롯은 자기 준비 객체만 변경한다.
   기존 Main 연결과 원천 세션은 읽기 전용이다. I/O나 발행은 작업 스레드에서 하지 않는다.
4. 모든 작업이 종료되고 오류가 없는 경우에만 정렬된 연결 순서로 기존 결과 digest를 만든다.
5. 기존 영속 기록·동기화 및 무할당 일괄 반영 경로로 발행한다.

작업 스레드가 실패하면 예외를 Main에 전달한다. 모든 시작된 스레드를 join한 뒤 준비
객체를 버리므로 기존 Main·강도·세대·병합 이력은 바뀌지 않는다. 스레드 일부만 생성된 뒤
나머지 생성이 실패한 경우도 같은 수명 순서를 지킨다.

## 설정과 자원

C++ MainGraph/PersistentMainGraph/RuntimeConfig의 `workers` 또는 `merge_workers`로
슬롯 수를 지정한다. 실제 슬롯은 연결 수와 설정 중 작은 값이며 호출 스레드도 한 슬롯을
담당한다. 0은 거부한다. C++ 기본값은 1이다.

MCP 설정에는 십진 문자열 `mergeWorkers`를 명시한다. 예제 값은 `"2"`이며 이 PC의 검사도
CPU 6·7에 제한했다. 더 많은 자원을 사용할 때 값을 변경할 수 있다. 작업 슬롯 수는
운용 설정이므로 영속 코어 결과를 바꾸지 않으며 재시작에서 바꿀 수 있다.

할당 예산은 작업들 사이에서 공유된다. 사용자 지정 upstream memory_resource는 여러
슬롯을 쓸 때 동시 할당/해제를 지원해야 한다. 기본 new_delete_resource는 이를 지원한다.
OS 스레드 스택과 표준 스레드 구현의 내부 할당까지 PMR 예산으로 계수했다는 뜻은 아니다.

## 검증 범위

병렬 검사 1,236개가 일반 실행·UBSan trap 실행에서 통과했다. 할당 실패 지점은 214곳이다.
기존 직렬 Main 검사 3,700개(할당 실패 733곳)도 통과했다.
MCP 실제 프로세스 검사 339개도 통과했으며 2슬롯 설정으로 여러 연결을 병합했다.

- 직렬과 두 슬롯 병합의 연결 강도·개정·모든 원경험 주소·전체 refinement digest를 대조한다.
- 할당 실패를 순서대로 주입하며 작업 스레드에서 발생한 예외도 관찰한다. 실패 시 기존
  그래프와 예산 사용량이 복구되는지 검사한다.
- 두 번째 스레드 생성에 EAGAIN을 주입해 먼저 시작된 작업의 join·정리를 검사한다.
  이 경우 실행되는 계산 슬롯은 호출 스레드와 먼저 생성된 하나뿐이다.
- 병렬로 저장한 메인을 1슬롯 및 2슬롯으로 각각 복구해 같은 기록 헤드와 코어 결과인지 확인한다.

## 남은 범위

현재 Main은 읽기·병합을 직렬 소유하고 그 안의 준비 계산만 병렬화한다. 비동기 작업 큐,
동시 읽기 스냅샷, 거대한 단일 연결의 분할·연결선 및 연결 내부 병렬화는 남아 있다.
속도 향상 배율이나 전체 입력 지연 달성은 이 기능 검사만으로 주장하지 않는다.
