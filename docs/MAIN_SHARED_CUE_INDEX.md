# Main이 소유하는 공유 정확 키 색인

MainGraph가 기록된 cue → (연결 ID, 원경험 시작 번호, 끝 번호)의 색인을 한 번
소유한다. 각 세션 ExperienceRouter는 Main 포인터와 발행 head만 보유한다.
동일한 Main을 여러 세션에 연결해도 각 세션에 전체 연결/키 색인을 복제하지 않는다.

## 발행과 검증

- 종료·발행된 원천의 실제 경험을 셔플하고 기존 SWEGCA 검증을 실행한다.
- 준비 단계에서 새 경험의 정확 키 구간과 기존 맥락 포털 구간을 함께 만든다.
- 연속한 같은 cue와 같은 연결은 기존처럼 한 구간으로 표현한다. 후보를 생략하지 않는다.
- 모든 할당은 영속 병합 발행 전에 수행한다. 이후 준비된 map 노드를 옮기고,
  기존 구간의 끝을 확장한다. 공개된 상태를 부분 수정한 뒤 할당하는 경로는 없다.
- 기존 병합 이력의 동일한 경험으로 복구되며 저장 형식과 셔플 결과 digest는 바뀌지 않는다.
- 연결 강도·관측·출처·세대 및 원경험 검증은 그대로 유지한다.

세션 head 갱신에는 할당과 경험 전체 순회가 없다. 이전 head의 Recall로 현재
Main을 Replay하는 것은 기존처럼 거부한다. 각 receipt가 고정한 원경험과 당시
강도는 이후 병합에도 유지된다. 독립적으로 발행된 세션을 직접 연결하는 기존
SessionRuntime 경로는 동일하게 유지한다.

세션별 증분 색인 갱신에만 사용했던 파생 변경 목록은 공유 색인으로 대체됐다.
Main generation, 원천 root, 병합 저널과 결과 검증은 삭제하지 않았다.

## 검증 및 한계

할당을 전부 거부한 상태에서 바뀐 head 갱신과 두 번째 route의 최초 Main 연결을
확인한다. 동일 cue의 연속 확장, 불연속 구간, 여러 연결·지역, 이전 receipt의 유지,
재시작 후 정확한 원경험 Replay를 검사한다.

이 변경은 세션 수만큼의 중복 색인을 제거한다. Main 자체의 연결·경험·cue/context
색인은 여전히 상주한다. 지역 디스크 적재/퇴거, 전체 4GB 운용 및 입력 1ms 상한의
완료 증거는 아니다.

## 병합 메타데이터 순회 통합

병합 후보의 원경험 주소 digest를 계산할 때 같은 reader에서 읽은 메타데이터로
새 context/cue 구간도 작성한다. 이전 연결의 prefix는 기존 순서대로 digest에
포함하고, 색인에는 이번에 추가된 경험만 넣는다. 원래의 두 순회를 하나로 합쳤으며
같은 index에서 context와 cue를 얻기 위한 중복 reader 호출도 제거했다.

SWEGCA 입장·셔플·판정·강도 계산은 이 순회 전에 그대로 수행된다. hash의 domain,
연결 순서, 원경험 주소 순서는 동일하다. 색인과 지역 분할의 모든 할당은 영속 발행
이전에 끝나며, 실패 시 후보를 폐기한다. 발행 후 노드 이동 경로는 변경하지 않았다.

CPU 6,7 / make -j2 빌드 후 Main graph 4221 checks, Persistent Main 1097 checks
통과. 할당 실패 후 공개 상태/메모리 보존, 지역 분할, cold 메타데이터, 원경험 Replay,
구간 연장·혼합 receipt 및 영속 복구를 검사했다. 벽시계 속도나 I/O 절감 비율은
이번 검사로 측정하지 않았다.

Main cue/context 색인은 여전히 키별 map과 구간별 map으로 전체 상주한다.
경험 메타데이터의 페이지 퇴거만으로 이 색인의 선형 상주량은 사라지지 않는다.
따라서 이번 중복 순회 제거를 대규모 Main의 4GB 운용 완료로 보고하지 않는다.
