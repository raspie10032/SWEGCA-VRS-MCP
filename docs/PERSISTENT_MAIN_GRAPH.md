# Main 병합의 영속 기록과 복구

2026-09-26. `PersistentMainGraph`는 기존 `MainGraph`의 SWEGCA 병합 결과를
기록하고 같은 원천·순서·셔플 조건으로 복구한다. 코어 판정식을 바꾸지 않는다.

## 발행 순서

1. 종료·발행된 세션만 받는다. 같은 세션 ID와 루트는 중복 강화하지 않는다.
2. 변경할 연결을 준비하고, 실제 경험을 셔플해 SWEGCA로 검증한다.
3. 세션 ID·원천 루트·세대·셔플 seed·step·결과 digest·이전 병합 주소를 기록한다.
4. 기록의 `fdatasync` 성공 뒤 준비한 연결과 병합 이력을 메모리에 반영한다.
   이 마지막 반영 구간에는 추가 할당이나 파일 작업이 없다.

기록 실패 후에는 해당 소유자의 그래프 접근·추가 병합을 막고 재개방을 요구한다.
동기화 오류 전에 완전한 바이트가 쓰였다면 재개방에서 그 기록이 발견될 수 있다.
오류를 곧바로 미발행으로 단정하지 않는다. 이 검사는 실제 전원 차단 내구성 실험은 아니다.

## 저장과 복구

- `control.block`에는 Main identity에 묶인 초기 강도·규칙 digest·블록 용량을 저장한다.
  쓰기 잠금을 유지해 같은 그래프의 중복 소유를 거부한다.
- `m-0000000000000000.block`부터 순서대로 병합 기록을 저장한다.
  기존 ExperienceBlock 체크섬·용량 검사·부분 기록 경계를 사용한다.
- 신규 블록은 임시 이름에서 헤더 동기화를 마친 후 덮어쓰기 없는 링크로 공개하고
  디렉터리를 동기화한다. 남은 임시 파일은 복구 대상에 포함하지 않는다.
- 재개방은 완전한 기록의 계보를 검사하고, Main의 원천 registry가 제공한 종료 세션으로
  실제 병합을 재실행한다. 연결별 코어 결과·원경험 주소 순서 digest까지 대조한다.
  저장된 강도를 그대로 대입하는 복구가 아니다.
- 원천 누락·다른 원천 루트·다른 규칙·불일치 결과는 복구 실패로 처리한다.
- 불완전 꼬리는 유지한다. 재개방 후 쓰기는 항상 새 블록에서 시작한다.
- 원경험은 원래 SessionStore에서 선택 주소로 읽는다. 원천 저장소 객체는 조회 동안
  살아 있어야 한다. 원천 SessionRuntime 캐시는 병합 뒤 해제할 수 있다.

## 검증

- 영속 Main 검사 29개: 일반 실행 및 UBSan trap 실행 통과.
- 중간 쓰기 실패, 완전 기록 후 동기화 실패, 재시작의 실제 기록 복구, 중복 무변경,
  정확한 원경험 읽기, 설정·원천 불일치 거부를 확인했다.
- 체크섬을 정상 재작성한 위조 결과 digest도 SWEGCA 재계산 불일치로 거부했다.
- 기존 Main 병합 검사 3,695개(할당 실패 지점 732곳)와 연결 복구 검사 65개 통과.
- 할당 자원 해제 후 공유 예산 사용량 0을 확인했다. CPU 6·7만 사용했다.

## 남은 범위

입력 라우터의 통합 Main 조회는 [Main 조회 문서](MERGED_MAIN_QUERY.md)에 기록했다.
자동 원천 registry, 종료 후 병합 스케줄러는 아직 남아 있다.
현재 복구는 전체 병합 이력을 재생한다. 대규모 체크포인트·분할 시작 경로는 미구현이다.
초기 생성 중 실패하면 불완전 디렉터리가 남을 수 있으며 자동 초기화 재시도는 제공하지 않는다.
동시 읽기 스냅샷, 전체 프로세스 RSS·저장량·I/O 제한, 실제 입력→Recall 지연도 별도 구현·검증 대상이다.
이 문서는 전체 VRS 완성이나 실제 서비스 배포를 뜻하지 않는다.
