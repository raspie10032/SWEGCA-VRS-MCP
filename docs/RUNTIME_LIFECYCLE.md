# Main 실행 객체와 세션 종료 후 병합

2026-09-26. `Runtime`은 MainSources, 영속 Main 그래프, 한 개의 임시 세션과 입력 라우터를
올바른 수명 순서로 소유하는 C++ 실행 객체다. 실제 MCP 서버나 클라이언트 훅 배포는 아니다.

## 세션과 입력

- `create/open`에서 Main을 생성하거나 실제 원천을 재검증해 복구한다.
- `start_session`은 새 임시 세션을 만들고 Main 조회 인덱스를 연결한다.
  `resume_session`은 지정한 기존 세션을 복구한다. 두 개를 동시에 소유하지 않는다.
- `input`은 라우터의 Déjà vu/Recall로 바로 들어간다. 앞에 병합·저장·스케줄 처리를 넣지 않는다.
- `retain`은 사용자·도구·모델 등 호출자가 전달한 원문/출처를 기존 불충분 경험의
  저장·셔플·코어 검증 경로로 보낸다. 관측값이 있는 경험은 `observe`를 사용한다.
  문자열 내용만으로 관측 결과를 발명하지 않는다.
- Replay와 Re-evidence는 같은 세션 라우터를 사용한다. 반환된 조회/Replay 객체는
  해당 세션 수명 안에서만 사용한다. 세션 종료 이후로 넘길 수 있는 영속 영수증은 아직 아니다.
- `receive`는 한 호출에서 입력의 Déjà vu/Recall을 먼저 수행하고 전체 이벤트를 즉시
  기록·셔플·검증한다. 반환된 Recall에는 기록 전 후보와 원경험 주소만 들어 있다.
  같은 임시 연결에 이번 이벤트가 추가돼도 불변 원경험은 정확히 Replay할 수 있다.
  모든 실제 세션 이벤트를 이 호출로 전달하는 클라이언트 훅은 남아 있다.

## 명시적 종료와 작업 처리

1. `end_session`은 SWEGCA 세션 상태에 따라 종료·원경험 발행을 수행한다.
2. 발행 완료 후 임시 소유자와 라우터를 해제한다. 발행 파일 자체가 영속 대기 작업이다.
3. `work(seed, step)`은 종료·발행된 미병합 원천만 처리한다.
4. 병합 후 살아 있는 새 세션의 Main 조회 인덱스를 갱신한다. Main 헤드가 바뀌지 않았으면
   전체 인덱스를 다시 만들지 않는다.

Runtime 파괴나 idle은 종료 이벤트가 아니다. 명시적으로 종료하지 않은 세션은 재시작 때도
활성이며 Main에 들어가지 않는다. 종료 뒤 발행 전에 멈춘 세션은 `resume_session` 후
명시적 `end_session` 재요청으로 발행을 마칠 수 있다.

이전 세션은 종료된 이후 다음 세션과 함께 존재할 수 있다. `work`가 현재 활성 세션을
종료·병합하지는 않는다. 현재 구현의 요청과 작업 처리는 Main이 직렬로 호출해야 한다.
별도 워커, 동시 스냅샷, 자동 백그라운드 wakeup은 아직 연결하지 않았다.

## 실패와 복구

- 종료/발행 실패 후 임시 소유자를 성급하게 버리지 않는다. 저장소가 사용 불가 상태면
  다시 열어 실제 디스크 상태를 복구해야 한다.
- 병합 쓰기 실패로 Main이 사용 불가가 되면 재시작 복구를 요구한다. 종료·발행된 원천은
  디스크에 남아 있어 다음 실행의 `work`가 미완료 병합을 이어간다.
- 인덱스 갱신 실패는 이미 완료된 병합을 취소하지 않는다. 낡은 Main 인덱스는 오류를 내며,
  다음 `work`에서 병합 중복 강화 없이 인덱스 갱신을 재시도한다.
- MainSources는 그래프보다 늦게 해제되고, 임시 라우터는 그래프보다 먼저 해제된다.

## 확인과 남은 범위

세션 수명 검사 36개가 일반 실행 및 UBSan trap 실행에서 통과했다. CPU 6·7만 사용했다.

세션 파괴 후 활성 유지, 명시적 종료 후 발행 작업 잔존, 새 세션 중 이전 세션 병합과 조회
갱신, 병합 쓰기 실패 후 재시작, 정확한 원경험 Replay, 끝난 세션 쓰기 거부를 검사했다.

클라이언트 훅/MCP 이벤트 수집, 비동기 작업 스케줄러, 대규모 분할·병렬 처리와 실제
입력→Recall 1ms 및 전체 자원 조건은 여전히 남아 있다.
