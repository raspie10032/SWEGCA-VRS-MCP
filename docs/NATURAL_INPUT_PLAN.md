# 자연 입력 연결 구현 우선순위

2026-09-27 사용자 요청: 구현이 쉽고 영향이 큰 부분부터 진행하고 장기목표로 등록.

## 절대 준수

보존·보강된 C++ SWEGCA 코어를 논리소자로 사용한다. 모든 VRS 결정은 코어를
통하며 셔플된 실제 경험에 대한 승인/거절/기권은 동일 연결의 강화/약화/유지다.
외부 의미 판정기로 대체하거나 해석 후보를 검증된 사실로 취급하지 않는다.
원문·출처·불확실성·반증과 과거 정정을 보존한다. 내부 실시간 LLM 호출은 0회.
사용자 입력 즉시 Déjà vu→Recall→선택 원경험 Replay→충돌 시 Re-evidence.
입력→Recall 진입은 사용자 최신 정정에 따라 5ms 미만, 코어 공정은 ns 시간대.
세션 전체는 임시 VRS에 실시간 반영, 임시 우선·적격 경험 부재 시 Main 조회.
Main 병합은 명시적 세션 종료 후에만 수행한다. Main이 판단·상태·권한을 소유한다.
분할·연결·병렬 처리, VRS 4GB RAM/625000000B/s 논리 I/O/500GB 조건 및 확장 설정 유지.
폐기 코드·후보 설계 참조, SQLite, Hermes, 외부 대체 판정, 프리빌트 휠 금지.
Claude 통신 중지, Palworld 보존, 빌드 CPU6-7/-j2, GitHub Actions/원격 push 금지.

## 현재 재사용할 기반

현재 저장소의 requirement_anchor.hpp, input_observation_scope 기반 scoped 연결,
related Recall/Replay, 원경험 계보 및 재시작 복구. 정확한 인용의 실재 검증은
의미 적합성이나 전체 요구 추출의 증거가 아니다. 기존 코어 판정식은 유지한다.

## 우선순위와 완료 증거

1. **여러 요구와 관측의 누락 없는 연결·전달** — 상대 난도 낮음, 영향 큼.
   기존에 명시된 requirement 인용/scoped 관측을 입력 원경험별로 발견·열거하여,
   관련 경험 하나만 전달되는 제한을 개선한다. 원문 주소와 범위를 보존하고
   관측 없는 항목/인용 없는 원문은 검증되지 않았음을 드러낸다. 열거 대상에
   없다는 이유로 완료로 판정하지 않는다. 페이지·자원 한도 초과 시 미전달 범위를
   명시하고 선택 원경험만 읽는다. 핵심 검증: 복합 요청의 한 부분만 지지돼도
   나머지가 통과하지 않음, 반박/기권 함께 전달, 임시/Main/재시작 동일성.

2. **자연 입력에서 출처가 있는 요구 후보 구성** — 상대 난도 중간, 영향 큼.
   명시적 목록·문장·인용 범위를 보존하는 구조 처리부터 시작한다. 분절은 의미
   판정이 아니며 누락한 텍스트도 보존한다. 대상·행위·금지·조건 해석은 후보로
   취급하고 실제 관측과 SWEGCA 검증에 연결한다. 단어 일치만으로 의미 동일성을
   승인하지 않는다. 핵심 검증: 한국어/영어, 다중 text, 부정·조건·인용문에서
   원문 손실 없음, 불명확한 후보의 기권, 입력→Recall 앞 처리 추가 없음.

3. **정정·금지·적용 범위의 경험 연결** — 상대 난도 중간 이상, 영향 큼.
   먼저 기존 turn/steer와 명시적 원경험/요구 참조를 활용한다. 어떤 요구를
   바꿨는지 출처를 연결하고 이전 요구를 지우지 않는다. 자연어만으로 참조가
   불명확하면 임의 교체하지 않는다. 핵심 검증: 일부 요구 정정 시 다른 요구
   보존, 취소/예외/범위 제한 보존, 재시작·Main 병합 후 같은 수정 계보.

4. **요구와 실제 결과의 적합성 검증 확대** — 상대 난도 높음, 최종 필수.
   기존 실제 파일 내용 관측처럼 검증 가능한 관계부터 코어 관측 소자로 연결한다.
   인용 일치와 관측의 실제 관련성/충분성을 구분한다. 범용 문장의 대상·관계·조건,
   표현이 다른 동일 목적, 복합 목적을 실제 경험으로 검증하는 범위를 넓힌다.
   지원하지 않는 의미 관계는 기권하며 전체 목적 충족으로 승격하지 않는다.
   핵심 검증: 명령 종료 성공/파일 일치만으로 잘못된 목적을 통과시키지 않음,
   지지·반박·불충분·후속 정정의 일관성, 미지원 관계 명시.

## 전체 목표의 남은 작업

위 1~4는 전체 VRS 완결의 우선 구현 순서이며 목표 축소가 아니다.
대규모 Main 탐색 맵 페이지 연결, 메모리 압박/캐시 운영, 자원 한도 및 실제 경로
5ms 검증, 설치된 에이전트의 실제 사용 검증도 완료해야 한다. 기능 완성 전에는
장기 모델 성능평가를 하지 않는다. 각 단계는 구현→의미 있는 회귀검증→로컬 커밋.
키워드 예제 통과나 관측 열거만으로 일반 자연어 의미 처리가 완성됐다고 하지 않는다.
