# 입력 수신과 기록 전 원경험 회상

2026-09-26. `Runtime::receive(original, seed, step)`를 추가했다.
기존 실행 객체와 코어 계보 검사를 조합하며 별도 의미 분류기나 LLM 호출은 사용하지 않는다.

## 순서

1. 원문의 media/content를 기존 입력 경로의 Déjà vu/Recall로 전달한다.
2. 기록 전에 존재하던 후보·연결 헤드·정확한 원경험 주소·현재 관측 경계를 보존한다.
3. 원문 전체와 출처를 임시 VRS에 기록하고 실제 경험을 셔플해 SWEGCA로 검증한다.
4. `ReceivedInput`으로 기록 전 Recall과 기록 결과를 함께 반환한다.
5. Main은 반환된 후보 중 필요한 원경험 하나를 선택해 Replay한다.

코드가 임의로 후보를 선택하거나 모든 원경험을 미리 읽지 않는다. 반환되는 후보에는
이번 수신 이벤트가 과거 기억처럼 섞이지 않는다. 원문만 있는 이벤트는 관측 결과가
불충분한 경험이며 승인으로 간주하지 않는다.

## 같은 임시 연결의 새 기록

자연 입력의 `InputRecall`이 원경험 주소를 직접 보유한다. Replay 때 같은 소유자의
연결인지, SWEGCA `assess_head_publication`에서 동일 개정 또는 이후 계보로 인정되는지,
기존 인덱스가 여전히 동일 원경험 주소를 가리키는지 확인한다. 통과하면 그 주소만 읽는다.

이전 강도를 현재 판정으로 바꾸지 않는다. `ReplayedInput`의 기억 헤드는 Recall 당시
상태를 유지하며, 재검증은 그때의 경계 이후에 실제 추가된 관측만 대상으로 한다.
계보·소유자·주소 불일치는 거부한다. 직접 연결 ID로 받은 빌린 후보 뷰는 여전히 최신
헤드를 요구한다. Main 병합으로 바뀐 자연 Recall도 기존의 재조회 요구를 유지한다.

## 확인

수신·수명 검사 81개가 일반 실행과 UBSan trap 실행에서 통과했다.
세션 런타임 회귀 검사 234개, Main 조회·복구 검사 70개도 통과했다.

사용자·모델·도구·시스템 출처를 순서대로 수신하면서 기록 전 후보 개수, 동일 연결의
기록 후 정확한 원경험 Replay, 새 관측 범위, 불충분 판정 유지, 원문·출처 보존을 확인했다.
NUL·비텍스트 바이트가 포함된 도구 출력도 원문 그대로 읽었다. 기록 실패는 수신 성공으로
반환되지 않으며 해당 임시 런타임이 사용 불가가 되는 것도 확인했다.

## 경계

현재는 C++ 수신 API다. 실제 Codex/Claude 세션 이벤트 수집, MCP 전송, 비동기 입력 큐는
아직 연결하지 않았다. 입력→Recall 시간과 수신 함수 전체 시간은 다르다. 후자에는 동기
기록·셔플·검증이 포함되므로 이 구현만으로 1ms 달성을 주장하지 않는다.
