# Main이 소유하는 세션별 최신 연결 목록

2026-09-26. `ConnectionCatalog`는 한 세션의 연결 ID를 최신 검증 기록 주소에 연결한다.
Main이 소유하며 같은 세션에 두 카탈로그 쓰기 소유자가 생기지 않도록 파일 잠금을 유지한다.
여러 세션을 통합한 전역 Main 그래프와 임시 우선 검색은 아직 남아 있다.

## SWEGCA 코어의 발행 조건

`head_publication_kernel.hpp`는 원본 아키텍처 I03/I07의 현재 상태·계보 결합 조건을
고정 크기 입력으로 검사한다. 저장 주소형은 코어와 VRS가 같은 `RecordAddress`를 공유한다.

- 예상한 이전 주소가 실제 현재 주소와 일치해야 한다.
- 이미 있는 연결을 갱신하려면 새 기록이 현재 기록을 계보 안에 포함해야 한다.
- 기록 순번이 크다는 사실만으로는 계보가 증명되지 않는다.
- 같은 주소의 개정·관측 수·강도가 다르면 무효다.
- 주소·수치·개정이 무효이거나 실제 관측이 없는 연결은 발행하지 않는다.
- 같은 상태를 다시 발행하면 변경 없이 끝낸다.

이 검사는 이미 계산된 연결 버전을 발행하는 조건이다. 의미기억 승격이나 외부 행동 권한을
부여하지 않는다. 관측의 승인·반려·기권과 강도 계산은 기존 SWEGCA 검증 경로를 따른다.

## 처음 루트와 변경 기록

카탈로그를 열기만 해서는 루트를 만들지 않는다. 세션에 원경험 기록이 생긴 뒤에는 연결 목록이
비어 있는 첫 루트를 발행할 수 있다. 연결이 생기기 전 빈 계보를 허용한다는 사용자 지시를 따른다.

루트를 갱신할 때는 **바뀐 연결과 이전 루트 주소**만 세션의 원경험 블록에 기록한다.
연결 목록 전체를 매번 복사·재기록하지 않는다. 여러 연결의 변경을 한 묶음으로 검사하고 발행한다.
같은 연결 ID를 한 묶음에 두 번 넣는 입력은 거부한다.

불변 변경 기록의 본문은 `SWGCCAT1`이다. 104바이트 헤더에 세대·이전 루트·행 수를 담고,
행마다 224바이트에 연결 ID·새 주소·개정·순번·관측 수·강도·예상 이전 주소를 담는다.
정수는 little-endian, 강도는 binary64 비트다.

현재 루트를 가리키는 `connections/current.block`에는 고정 96바이트 본문 `SWGCREF1`을 둔다.
새 포인터 파일을 완성·동기화한 뒤 이름을 원자적으로 교체하고 디렉터리를 동기화한다.
파일 작업 후 메모리 반영에 필요한 새 목록 노드는 미리 할당한다.

## 복구와 실패 처리

- 현재 포인터에서 이전 루트 계보를 따라 변경 목록을 복원한다.
- 각 연결 갱신의 실제 부모 계보를 확인하고 코어 발행 조건을 다시 적용한다.
- 최종 연결마다 원경험과 셔플 이력을 SWEGCA로 재실행한다. 목록에 적힌 강도·개정과 실제
  복구 결과가 일치해야 카탈로그를 사용할 수 있다.
- 쓰기 실패 뒤에는 해당 카탈로그의 조회·갱신을 거부하고 다시 열어 실제 디스크 상태를 확인한다.
- 포인터 교체 전 실패하면 이전 루트가 남는다. 교체 후 동기화가 실패하면 디스크에 새 루트가
  보일 수 있으므로 이전 상태라고 단정하지 않는다. 복구한 실제 루트의 이전 주소 조건으로 재시도를 검사한다.
- 미완료·미발행 변경 기록과 준비 파일을 원경험 삭제로 처리하지 않는다.

세션 종료 기록은 현재 카탈로그 포인터의 체크섬도 포함한다. 종료 후 유효한 과거 포인터로
바꿔 놓아도 세션 재시작 검사에서 불일치가 드러난다. 종료된 세션의 카탈로그 갱신은 세션 코어가 거부한다.

## 검증

- 전체 `make -j2 check` 통과. 새 카탈로그 **60회 확인**은 UBSan trap 구성에서도 통과했다.
- 원경험 전 루트 발행 거부, 첫 빈 목록, 최초 연결 등록, 두 연결의 일괄 발행을 검사했다.
- 오래된 예상 주소와, 현재 주소를 거짓으로 제시한 분기 갱신을 거부했다.
  분기의 순번이 현재 상태보다 더 큰 경우에도 실제 계보가 없으면 거부했다.
- 잘못된 일괄 변경에서 다른 정상 연결만 먼저 반영되지 않음을 확인했다.
- 재시작 후 연결 ID로 최신 주소를 찾아 원경험·코어 판정까지 복원했다.
- 종료 상태, 다른 세션의 연결, 중복 쓰기 소유자·중복 변경 대상을 검사했다.
- 포인터 `rename` 실패와 교체 후 디렉터리 `fsync` 실패를 테스트 실행파일에서 주입했다.
  각각 실제 남은 루트를 복구하고 중복·오래된 재시도가 덮어쓰지 못함을 확인했다.
- 과거의 유효한 포인터로 종료된 루트를 바꾸면 거부했다.
- 체크섬이 유효한 변경 기록·포인터라도 강도를 거짓으로 적으면 코어 재실행 대조에서 거부했다.

## 시간과 남은 범위

CPU 6 고정, GCC 16.2.1, `-O3 -march=native -ffp-contract=off`.
100,000회 예열 뒤 100,000회 호출 묶음 31개의 평균 중앙값:
코어의 연결 주소 발행 조건 검사 **8.24839ns**.
다른 CPU의 UBSan 빌드·검사와 Palworld 실행을 유지했다.
이는 계보 파일 읽기·저장·동기화를 제외한 코어 조건 검사다.
원문 출력은 `measurements/head-publication-20260926.txt`에 보존했다.

현재 카탈로그와 세션 소유자에는 직렬 접근이 필요하다. 입력 훅에서 사용할 동시 조회 구조와
실제 입력→Recall 1ms 조건은 미검증이다. 재시작 시 변경 계보·최신 연결을 검증하므로 긴 이력의
체크포인트 및 대규모 분할 색인도 남아 있다.

다음 통합 범위는 세션별 임시 목록과 전역 Main 목록의 연결, 원경험 주소 해결,
종료 후 그래프·강도 병합, 일반 입력의 경험 처리, 기억 4단계다.
