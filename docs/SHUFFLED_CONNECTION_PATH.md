# 기록된 관측값의 셔플과 SWEGCA 연결 갱신

2026-09-26. `codex/vrs-completion-20260926`.

## 실행 경로

```text
관측값과 원문을 같은 원경험 레코드에 기록
  → 블록 주소를 통해 원경험을 선택해서 읽음
  → 체크섬이 확인된 레코드에서 관측값을 복원
  → 해당 연결의 경험 묶음을 셔플
  → SWEGCA 관측 수용 규칙과 출처·맥락별 기여 계산
  → SWEGCA 3상 판정
  → 같은 연결의 강도에 승인 ×1.01 / 반려 ×0.995 / 기권 유지
```

이 경로는 실험·도구 등이 **관측 결과를 기록한 경험**에 대해 구현됐다.
자연어 원문에서 관측 결과를 생성하는 입력 처리, 전체 경험 그래프, 기억 4단계,
세션 종료 후 메인 병합과 연결 상태의 영속 발행은 아직 미구현이다.

## 코어와 VRS의 역할

- `evidence_observation_kernel.hpp`: 원본의 관측 유효성·만료·불충분·중복 수용 규칙과
  `(축, 출처, 맥락)` 묶음의 유효 기여 계산. 별도 안정성 임계값은 추가하지 않았다.
- 보존된 `judge_evidence`: 판정식과 수치 연산 순서를 유지한다.
- 보존된 `revise_connection_strength`: 코어 판정에 따른 강도 계산.
- VRS `Connection`: Main이 한 객체를 소유하고 직렬로 접근한다. 경험 주소·개별 관측값을
  보유하고, 셔플·자료구조·메모리 계수·결과 기록을 수행한다. 서로 다른 연결은 병렬 처리할 수 있다.

매 셔플 주기마다 개별 경험에서 집계를 새로 만든다. 이전 집계는 연결 객체에 저장하지 않는다.
셔플은 명시적인 Fisher–Yates와 `mt19937_64`의 편향 없는 정수 선택으로 수행한다.
주기 결과에 실제 방문 순서와 각 경험의 수용·제외 사유를 보존한다. 순서만으로 증거의 수가
늘어나지 않으며, 같은 원경험 주소는 한 번만 기여한다.

동일 출처·맥락의 기여는 원본 SWEGCA처럼 그룹의 지지/전체, 반증/전체 비율이다.
최근 결과 창은 원본의 관측 처리 순서를 따른다. 여기서는 그 순서가 기록된 셔플 방문 순서다.
만료된 경험과 불충분 경험은 관측값과 주소를 유지하고 현재 검증 기여에서 제외한다.
기권 결과와 무효 입력의 사유를 그대로 보존한다. 증거가 한 건도 수용되지 않으면 보존 코어의
개정 0 계약에 따라 무효 입력 기권으로 남으며 연결 강도와 개정을 바꾸지 않는다.

## 저장된 값과 연결의 결합

`ExperienceEvidence`는 기록 또는 검증된 블록 읽기에서만 생성할 수 있다. 관측값과
원문 주소를 외부에서 따로 수정할 수 없다. 연결은 다른 가설 ID의 레코드를 거부한다.
관측값이 기록돼 있다는 사실만으로 그 내용이 참이라고 간주하지 않는다.

레코드 본문 형식은 `SWGCEVD1`이다. 고정 176바이트의 접두부에 가설·출처·맥락·생산자 ID,
만료 정보, 생산자 확신도, 축과 관측 결과, 원문 미디어 타입·본문 길이를 담는다.
그 뒤 원문 미디어 타입과 원문 바이트를 그대로 저장한다. 시간·세션·출처는 바깥 원경험
레코드의 정보를 유지한다. 관측값 주소는 블록 레코드의 체크섬에서 정한다.
모든 정수는 little-endian, 확신도는 binary64 비트로 기록한다. 구조체의 패딩을 저장하지 않는다.

`Connection::refine`는 해당 객체 안에서 판정과 강도 적용을 끝낸다. 별도 판정을 다른 연결에
적용하는 API는 없다. 반환 결과는 연결 ID, 전후 개정, 시드, 검증 시점, 방문 순서, 집계와
코어 판정을 보존한다. 반환된 결과가 World·의미기억·외부 행동 권한을 부여하지 않는다.

모든 가변 크기 버퍼는 VRS `MemoryBudget`을 사용한다. 연결과 반환 결과보다 예산 객체가
오래 살아 있어야 한다. 검증 도중 할당이 실패하면 이전 강도·개정·경험을 그대로 유지한다.
이후 `PersistentConnection`이 준비와 반영 사이에 영속 기록을 연결하고 지정된 헤드에서
재시작 복구를 수행하도록 확장됐다. [연결 복구 문서](PERSISTENT_CONNECTIONS.md)를 참조한다.
최신 Main 루트와 통합 트랜잭션은 남은 작업이다.
